# Smoke test toàn đường đi

## Mục tiêu
Chạy một smoke test có đầu vào và kết quả cụ thể qua client → ALB → Nginx → Node → RDS. Đầu vào là tuyến ngày 9 và nhánh HTTPS ngày 10 nếu đã thực hiện; bài không tạo tài nguyên cloud mới, nhưng hạ tầng đang chạy vẫn có thể tính phí.
## Hiểu nhanh
`/health` chỉ chứng minh Node phản hồi. `/ready` thêm kiểm tra DB nhưng chưa chứng minh luồng lưu và lấy link đúng. `POST /shorten` nhận JSON URL và trả 201 gồm code/shortUrl. `GET /r/:code` trả 302 với Location trỏ URL gốc. Không dùng `curl -L` trong phép thử redirect vì tự follow sẽ che response 302 của app và có thể chuyển sang website ngoài.
`PUBLIC_BASE_URL` phải là URL client thực sự sử dụng, không phải loopback hoặc private IP. Node đọc biến runtime; sửa `.env` trên laptop không thay app EC2. Không có đăng nhập, rate limit hay bảo vệ lạm dụng được chứng minh trong core demo, nên kết quả này chưa đủ để gọi dịch vụ sẵn sàng production.
## Thực hành
Chạy Bash trên laptop, có curl và Python 3. Đặt base không có dấu `/` cuối; dùng domain HTTPS nếu đã xác minh TLS, hoặc ALB HTTP với URL test công khai khi chưa có domain:
```bash
export LAB_BASE_URL=https://DOMAIN_BAN_SO_HUU
# Nhánh chưa domain: http://ALB_DNS_THAT
export LAB_TEST_DIR=$(mktemp -d)
chmod 700 "$LAB_TEST_DIR"
curl -fsS --max-time 10 "$LAB_BASE_URL/health"
curl -fsS --max-time 10 "$LAB_BASE_URL/ready"
LAB_CREATE_STATUS=$(curl -sS --max-time 15 \
  -o "$LAB_TEST_DIR/create.json" -w '%{http_code}' \
  -H 'Content-Type: application/json' \
  --data '{"url":"https://example.com"}' "$LAB_BASE_URL/shorten")
printf 'create_status=%s\n' "$LAB_CREATE_STATUS"
if [ "$LAB_CREATE_STATUS" != 201 ]; then
  cat "$LAB_TEST_DIR/create.json"
  printf '\nDừng tạo link: cần xử lý lỗi trước.\n'
else
export LAB_CODE=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["code"])' "$LAB_TEST_DIR/create.json")
python3 -c 'import json,sys; x=json.load(open(sys.argv[1])); print(x["shortUrl"])' "$LAB_TEST_DIR/create.json"
curl -sS --max-time 10 -D "$LAB_TEST_DIR/redirect.headers" \
  -o /dev/null -w 'redirect_status=%{http_code}\n' "$LAB_BASE_URL/r/$LAB_CODE"
cat "$LAB_TEST_DIR/redirect.headers"
curl -sS --max-time 10 -o /dev/null -w 'missing=%{http_code}\n' \
  "$LAB_BASE_URL/r/definitely-missing-day12"
fi
```
Trước khi gọi redirect, nếu create_status khác 201 thì dừng và đọc body; không cố parse code từ lỗi. So sánh shortUrl với `$LAB_BASE_URL/r/$LAB_CODE`. Nếu sai base, sửa đúng một biến trong file runtime trên EC2 bằng editor, nạp lại cấu hình theo PM2 ngày 7 và thử tạo link mới; không in DATABASE_URL. Giữ code vừa tạo cho bài reboot.
## Kiểm tra kết quả
`/health` 200 và JSON status ok; `/ready` 200; tạo link 201, code không rỗng; shortUrl đúng base; redirect 302 với Location `https://example.com`; code không tồn tại 404. Lưu cả HTTP status và thời điểm UTC, không chỉ body. Một lỗi 404 dự kiến không phải sự cố 5xx. Trên CloudWatch JSON log phải có path/status tương ứng sau độ trễ thu thập.
## Lỗi thường gặp
HTTP 301 do listener redirect là dấu hiệu bạn gọi HTTP trong nhánh HTTPS; đặt base HTTPS để POST không bị client đổi method khi follow. Body thiếu Content-Type hoặc JSON sai có thể gây lỗi validation. SG ALB chỉ cho IP cũ khiến laptop mạng mới timeout; cập nhật đúng nguồn hẹp, không mở public DB. TLS lỗi phải sửa trust/hostname, không dùng -k để đạt bài.
