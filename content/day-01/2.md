# Client, server và database

## Mục tiêu

Phân biệt trách nhiệm của ba thành phần bằng hai tình huống tạo link và mở link. Bạn sẽ lập bảng dữ liệu đi qua từng ranh giới, đồng thời xác định điều gì bị mất khi restart một tiến trình.

## Hiểu nhanh

Client khởi tạo request và diễn giải response. Client có thể là trình duyệt, `curl` hoặc một ứng dụng khác. Server trong demo là tiến trình Node.js nhận request HTTP trên một cổng; EC2 sau này chỉ là nơi chứa tiến trình đó. PostgreSQL là dịch vụ dữ liệu riêng: nó nhận câu SQL, áp dụng ràng buộc và lưu hàng dữ liệu.

Với `POST /shorten`, dữ liệu đầu vào là URL. Server quyết định chấp nhận URL nào và tạo `code`. Bảng `links` giữ quan hệ code–URL. Với `GET /r/:code`, client chỉ gửi code, server tra DB rồi trả URL qua header `Location`. Client không cần biết hostname DB hoặc mật khẩu PostgreSQL. Không đưa `DATABASE_URL` vào JavaScript chạy trong trình duyệt: đó là cấu hình cho server.

Bộ nhớ Node.js, dữ liệu DB và ổ đĩa đều có vòng đời khác nhau. Một biến Map trong Node.js biến mất khi restart. PostgreSQL có cơ chế lưu bền vững, nhưng nếu bạn xóa volume local hoặc xóa DB trên cloud thì dữ liệu vẫn có thể mất. Từ “database” không thay thế cho backup và kiểm tra restore.

## Thực hành

Tạo bảng bốn cột trong ghi chú: “Tình huống”, “Client gửi”, “Server làm”, “DB làm”. Điền hai dòng:

- Tạo link: JSON URL → xác thực và sinh code → INSERT hàng mới.
- Mở link: path chứa code → tra cứu và tạo response → SELECT URL theo code.

Thêm cột thứ năm “Có cần giữ bí mật?”. URL ví dụ `https://example.com` là dữ liệu kiểm thử công khai; mật khẩu DB phải giữ riêng phía server. Code ngắn không được coi là cơ chế bảo mật cho URL bí mật. Ai đoán hoặc nhận được code có thể thử mở nó.

Cuối cùng mô phỏng restart: gạch bỏ toàn bộ bộ nhớ server nhưng để bảng DB nguyên vẹn. Viết xem một request mở code cũ còn thành công không. Làm lại với tình huống xóa bảng `links` để thấy restart và mất dữ liệu là hai sự kiện khác nhau.

### Theo dõi vòng đời dữ liệu

Điền [bảng sự cố và dữ liệu](https://github.com/dattk2002/aws-daily-lab/blob/main/labs/foundations/01-2-data-lifetimes.csv) trước khi xem đáp án. Giả sử link đã được ghi thành công, dữ liệu PostgreSQL nằm trên volume riêng và cấu hình DB vẫn giữ nguyên:

| Sự kiện | Trong lúc sự kiện diễn ra | Sau khi khôi phục |
| --- | --- | --- |
| Restart Node.js | Request đến app có thể lỗi | Code cũ vẫn tra được trong DB |
| Restart PostgreSQL, giữ volume | App có thể trả lỗi khi truy vấn | Code cũ vẫn còn nếu DB phục hồi bình thường |
| Xóa volume DB rồi tạo DB rỗng | Không có dữ liệu cũ để đọc | Cần backup hoặc nguồn phục hồi khác |

Giữ dữ liệu không đồng nghĩa phục vụ liên tục: restart DB có thể làm gián đoạn request dù không mất hàng đã lưu. Không chạy lệnh xóa volume để làm bài này.

Ở mô hình local, client gọi HTTP cổng 3000; Node.js kết nối PostgreSQL cổng 5432 theo cấu hình lab. Node.js là server đối với browser nhưng là client đối với PostgreSQL. `localhost` luôn chỉ máy hoặc môi trường mạng của tiến trình đang dùng nó: browser trên laptop gọi `localhost` sẽ không đến EC2. Khi thêm Nginx/ALB, cổng công khai sẽ được thiết kế riêng; không mở 5432 ra Internet để sửa lỗi kết nối HTTP.

## Kiểm tra kết quả

Đáp án mong đợi: restart Node.js vẫn mở được code cũ nếu DB còn dữ liệu và kết nối hoạt động; xóa bảng làm thao tác đọc thất bại hoặc không còn tìm thấy ánh xạ. Client không tự phục hồi dữ liệu đã bị xóa chỉ bằng cách gửi lại code.

Bạn cần chỉ ra được hai kết nối tách biệt: client → HTTP server và server → PostgreSQL. Khi client nhận timeout, chưa thể kết luận DB hỏng; có thể kết nối đầu tiên chưa đến được Node.js. Bảng của bạn nên ghi mỗi kết nối có protocol, cổng và cơ chế kiểm tra riêng.

Trong bảng sự cố, tách hai kết luận “dữ liệu còn” và “request lúc đó thành công”. Với ca mất volume, restart Node.js không phải bước phục hồi dữ liệu. Với ca browser dùng sai `localhost`, hãy sửa địa chỉ API trước khi kiểm tra quyền PostgreSQL.

## Lỗi thường gặp

Đặt mật khẩu DB vào frontend vì “frontend cần dữ liệu” làm lộ quyền truy cập. Cho browser truy cập PostgreSQL trực tiếp cũng bỏ qua ranh giới kiểm soát của API. Một lỗi mô hình khác là đồng nhất một máy EC2 với một server ứng dụng: một máy có thể có nhiều tiến trình và một ứng dụng có thể chạy trên nhiều máy.

## Dọn dẹp

Bài chỉ dùng ghi chú, không mở cổng hoặc tạo database. Giữ bảng trách nhiệm để đối chiếu với biến môi trường ở ngày 3; không chèn mật khẩu thật vào ghi chú dùng làm bằng chứng công khai.
