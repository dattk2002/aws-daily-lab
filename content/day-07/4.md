# Quản lý process và phục hồi sau reboot bằng PM2

## Mục tiêu

Chạy demo dưới tên PM2 `aws-daily-lab`, tự khởi động lại cùng user `labapp` sau reboot, đồng thời giữ secrets trong file runtime ngoài Git. Phải kiểm tra reboot thật trước khi coi persistence hoàn tất.

## Hiểu nhanh

PM2 quản lý process hiện tại; startup hook tích hợp với systemd để khởi động PM2 khi máy bật; `pm2 save` lưu danh sách cần phục hồi. Cần cả startup hook lẫn danh sách đã lưu. Không chạy một daemon PM2 bằng root và một daemon khác bằng app user rồi đọc nhầm trạng thái.

Secrets được nạp bởi wrapper lúc process khởi động thay vì ghi thẳng vào ecosystem file trong repository. PM2 vẫn có dữ liệu process và log dưới home app user; giới hạn quyền home/.pm2, không chia sẻ dump hay output environment. Dùng shell mới chưa source app.env để tránh PM2 kế thừa DATABASE_URL từ phiên quản trị.

## Thực hành

Vào một shell mới bằng `sudo -iu labapp`. Cài PM2 trong prefix riêng của user rồi tạo wrapper:

```bash
npm install --global pm2 --prefix /home/labapp/.local
export PATH="/home/labapp/.local/bin:$PATH"
install -d -m 700 /home/labapp/bin
cat > /home/labapp/bin/start-app.sh <<'APP'
#!/bin/bash
set -euo pipefail
set -a
source /etc/aws-daily-lab/app.env
set +a
cd /opt/aws-daily-lab/labs/url-shortener
exec /usr/bin/npm start
APP
chmod 700 /home/labapp/bin/start-app.sh
pm2 start /home/labapp/bin/start-app.sh --name aws-daily-lab --interpreter /bin/bash --cwd /opt/aws-daily-lab/labs/url-shortener
pm2 save
chmod 700 /home/labapp/.pm2
pm2 startup systemd -u labapp --hp /home/labapp
```

Wrapper trên do bạn tự viết, không chứa secrets. PM2 in một lệnh `sudo env PATH=... pm2 startup ...`: đọc đúng user, home và path rồi chạy nguyên lệnh đó từ phiên có sudo (`ec2-user`). Không cấp sudo cho `labapp` để thực hiện bước này. Ghi version PM2 đã cài để lần sau có thể pin version đã kiểm tra.

Kiểm tra `systemctl status pm2-labapp` từ phiên quản trị; sau đó chủ động `sudo reboot` máy lab. Chờ máy trở lại, mở phiên mới và dùng `/home/labapp/.local/bin/pm2 list` trong shell `labapp`, rồi curl `/health` và `/ready` tại loopback.

## Kiểm tra kết quả

Sau reboot, process `aws-daily-lab` online với user `labapp`, health 200 và ready 200 mà không source env thủ công. `systemctl is-enabled pm2-labapp` phải báo enabled. Không chỉ chụp PM2 online trước reboot. Thay Node major hoặc đường PM2 có thể yêu cầu tạo lại startup hook; PATH của service phải tìm đúng Node.

## Lỗi thường gặp

Không `pm2 save` làm danh sách reboot thiếu app. Chạy `sudo pm2 list` xem daemon root nên có thể thấy rỗng dù app user đang chạy. Restart sau khi đổi env file dùng wrapper sẽ đọc file mới; tránh in `pm2 env` vì có thể lộ dữ liệu runtime. `PUBLIC_BASE_URL` không tự đổi theo public IPv4 mới sau stop/start.

## Dọn dẹp

Nếu tiếp tục, giữ startup và app cho Nginx. Nếu tháo riêng process, trong shell app user chạy `pm2 delete aws-daily-lab` rồi `pm2 save --force`; kiểm tra không có process khác cần giữ. Tắt startup hook bằng lệnh `pm2 unstartup` được in, chạy admin khi cần. Teardown EC2/RDS vẫn là bước riêng để dừng chi phí cloud.
