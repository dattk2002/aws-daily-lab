# Smoke test từ tạo link đến redirect

## Mục tiêu

Kiểm tra đủ hành vi demo trên EC2: liveness, readiness, tạo link 201, redirect 302 và mã không tồn tại 404. Lưu bằng chứng đủ chẩn đoán mà không thu thập credentials hoặc URL riêng tư.

## Hiểu nhanh

Smoke test là vài kiểm tra ngắn cho tuyến sử dụng quan trọng sau deploy. Nó không thay thế unit tests, kiểm tra tải hoặc đánh giá bảo mật. Với URL shortener, `POST /shorten` ghi DB; `GET /r/:code` đọc DB và trả Location. Vì vậy test tạo rồi redirect kiểm tra nhiều lớp hơn health đơn thuần.

Điều kiện: PM2 đã sống sau reboot, Node bind loopback 3000, RDS TLS verified và role app có schema. Nginx chưa triển khai nên thực hiện curl bên trong EC2. `PUBLIC_BASE_URL` có thể là public IPv4 cho bước Nginx ngày sau; hôm nay shortUrl chưa nhất thiết mở được từ laptop. Lấy `code` trong response và gọi loopback để xác minh phần app, đồng thời kiểm tra nội dung shortUrl riêng.

## Thực hành

Trong EC2, chạy các request bằng URL công khai không nhạy cảm:

```bash
curl -i http://127.0.0.1:3000/health
curl -i http://127.0.0.1:3000/ready
curl -i -H 'Content-Type: application/json' \
  --data '{"url":"https://example.com"}' \
  http://127.0.0.1:3000/shorten
```

Đọc JSON từ request cuối và lấy trường `code`, không đoán mã. Thay `<CODE_VUA_NHAN>` trước khi chạy:

```bash
curl -i http://127.0.0.1:3000/r/<CODE_VUA_NHAN>
curl -i http://127.0.0.1:3000/r/this-code-does-not-exist-in-my-lab
```

Không thêm `-L` ở lần đầu vì nó theo redirect và che status 302 ban đầu. Sau khi xác nhận Location đúng, bạn có thể dùng trình duyệt ở giai đoạn Nginx. Nếu mã thử 404 vô tình có sẵn, chọn mã khác chưa tạo. Đối chiếu database bằng psql `labapp`, cùng cấu hình TLS ngày 06: `SELECT code, url, created_at FROM links WHERE code = '<CODE_VUA_NHAN>';`. Chỉ thay code của chính lab, không nối input bất kỳ thành SQL trong ứng dụng.

## Kiểm tra kết quả

Bảng kết quả mong đợi: health 200 với status ok; ready 200; shorten 201 có code/shortUrl; redirect 302 với `Location: https://example.com`; unknown code 404. Truy vấn DB có đúng một record tương ứng và timestamp. Ghi giờ, SHA deploy, code test và status. ShortUrl phải dùng PUBLIC_BASE_URL đã đặt cộng `/r/<code>`; nếu nó vẫn là localhost thì sửa cấu hình trước khi công bố endpoint.

## Lỗi thường gặp

Redirect về sai host thường do PUBLIC_BASE_URL, không phải DNS database. 201 nhưng GET mã vừa tạo 404 có thể do nhập sai code hoặc hai app đang trỏ DB khác nhau; kiểm tra process và cấu hình có chọn lọc, không in secret. Ready 503 nhưng health 200 là tín hiệu phụ thuộc DB hỏng, không phải lý do restart Nginx.

## Dọn dẹp

Có thể giữ một record `https://example.com` cho bài proxy; nếu muốn xóa, dùng psql với `DELETE FROM links WHERE code='<CODE_VUA_NHAN>' AND url='https://example.com';` sau khi kiểm tra đúng record. Không xóa toàn bảng. Giữ PM2/EC2/RDS cho ngày 08 hoặc teardown theo tài nguyên đã ghi nếu dừng; app ngừng chạy không đồng nghĩa cloud ngừng tính phí.
