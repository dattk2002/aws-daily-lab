# Cài dependencies và chạy thử foreground

## Mục tiêu

Cài dependency theo lockfile bằng user ứng dụng, chạy `db:init`, rồi chứng minh `/health` và `/ready` khi app còn chạy foreground. Đây là mốc tách lỗi package, lỗi database và lỗi process manager.

## Hiểu nhanh

`npm ci --omit=dev` tái tạo dependency production từ lockfile; nó không chữa lockfile không khớp package.json. Không chạy bằng sudo trong source tree. `npm run db:init` là script của demo để tạo bảng `links` idempotently, không phải migration tự động xóa hoặc sửa mọi schema cũ. `/health` cho biết HTTP process sống, `/ready` kiểm tra database; một health 200 không chứng minh DB đang dùng được.

Điều kiện: source đúng SHA tại `/opt/aws-daily-lab`, app env và CA đúng quyền, DB/schema ngày 06 và không có process khác chiếm cổng 3000. Dùng hai phiên EC2: phiên một chạy app, phiên hai gửi curl. Chưa cần mở SG 3000 ra Internet và chưa cần Nginx.

## Thực hành

Trong shell `labapp`, nạp env ngoài repo và chạy từ đúng thư mục. Việc source chỉ dùng file bạn vừa tự tạo và đã kiểm tra, vì Bash có thể thực thi nội dung của nó:

```bash
cd /opt/aws-daily-lab/labs/url-shortener
npm ci --omit=dev
set -a
source /etc/aws-daily-lab/app.env
set +a
npm run db:init
npm start
```

Không bật `set -x` vì nó có thể in secrets. Nếu cài dependencies báo thiếu bộ nhớ, xem log và dung lượng trước khi thử lại; không chuyển sang root. Trong phiên EC2 thứ hai:

```bash
curl --fail --show-error http://127.0.0.1:3000/health
curl --fail --show-error http://127.0.0.1:3000/ready
sudo ss -lntp 'sport = :3000'
```

Chờ `/ready` trả 200 trước khi tuyên bố kết nối DB thành công. Thử một request sai cấu trúc có chủ đích bằng `curl -i -H 'Content-Type: application/json' -d '{}' http://127.0.0.1:3000/shorten`; nó phải bị từ chối với 4xx, không crash process. Không dùng password trong payload hoặc ghi toàn bộ env để debug.

## Kiểm tra kết quả

`db:init` kết thúc không lỗi; `/health` trả JSON `{ "status": "ok" }`; `/ready` có HTTP 200. Socket chỉ bind `127.0.0.1:3000`, không `0.0.0.0:3000`. Sau request sai, gọi lại health vẫn thành công. Ghi SHA, Node version và các HTTP status, không ghi DATABASE_URL. Kiểm chứng này chỉ từ loopback, chưa chứng minh request Internet qua Nginx.

## Lỗi thường gặp

`EADDRINUSE` nghĩa là cổng đã có listener; tìm PID rồi xác định process, không kill tất cả Node trên máy. Health tốt nhưng ready 503: xem lỗi TLS/network/user/schema, không mở inbound EC2 5432. `npm ci` báo lock mismatch: sửa và kiểm tra source ở môi trường phát triển, không dùng cài tự do trên server để che sự lệch.

## Dọn dẹp

Nhấn Ctrl+C trong phiên foreground trước khi chuyển sang PM2. Dùng `unset DATABASE_URL PGSSLROOTCERT HOST PORT PUBLIC_BASE_URL` hoặc đóng shell đã source để PM2 ở bài sau không kế thừa secret không cần thiết. Giữ dependencies/schema; đừng xóa bảng sau mỗi smoke test. EC2/RDS tiếp tục có thể tính phí trong lúc app dừng.
