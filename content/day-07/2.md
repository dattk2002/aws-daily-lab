# Giữ secrets ngoài Git và bật TLS cho app

## Mục tiêu

Tạo cấu hình runtime ở `/etc/aws-daily-lab/app.env`, chỉ admin và nhóm app đọc được, với database URL đầy đủ và CA bundle. Giải thích vì sao `.env.example` local không phải cấu hình production.

## Hiểu nhanh

Docker local dùng user/password/database `lab` trong `labs/url-shortener/compose.yaml`; các giá trị giả đó không được đem lên RDS. App dùng `DATABASE_URL`, `HOST`, `PORT`, `PUBLIC_BASE_URL` và `PGSSLROOTCERT`. Demo hỗ trợ CA tùy chọn, nhưng với RDS bài này bắt buộc cấu hình CA và xác minh TLS. Để app chỉ nhận request qua Nginx, giữ `HOST=127.0.0.1`.

URL có password phải percent-encode các ký tự dành riêng trong username/password: ví dụ ký tự `@` trong password được biểu diễn `%40`. Chỉ encode phần credentials, không encode cả URL. Không đưa secret vào command line để encode, vào chat hoặc trang kiểm tra URL trực tuyến. Dùng password manager/công cụ offline phù hợp và lưu trực tiếp bằng editor được cho phép. File env sẽ được source bởi Bash ở bài 07-4 nên giá trị cần được trích dẫn đúng; không đặt shell command trong file.

## Thực hành

Từ phiên quản trị, giữ thư mục CA công khai đã tạo ngày 06; tạo file secret một lần rồi mở editor:

```bash
sudo install -o root -g labapp -m 640 /dev/null /etc/aws-daily-lab/app.env
sudoedit /etc/aws-daily-lab/app.env
```

Không chạy lại `install /dev/null` khi file đã chứa cấu hình vì nó làm trống file. Nội dung mẫu dưới đây chỉ chứa placeholder, hãy thay bằng thông tin của bạn trong editor, không dán bản thật vào repository:

```bash
DATABASE_URL='postgresql://labapp:<PASSWORD_DA_PERCENT_ENCODE>@<RDS_ENDPOINT_DNS>:5432/lab?sslmode=verify-full'
PGSSLROOTCERT='/etc/aws-daily-lab/global-bundle.pem'
HOST='127.0.0.1'
PORT='3000'
PUBLIC_BASE_URL='http://<EC2_PUBLIC_IP>'
```

Không thêm `sslmode=no-verify` hay tắt kiểm tra chứng chỉ. Với CA tường minh, demo dùng xác minh CA/hostname và xử lý tham số SSL của URL để tránh parser `pg` ghi đè CA. `PUBLIC_BASE_URL` là địa chỉ client sẽ mở; không đặt loopback nếu client ở máy khác. Khi có domain/HTTPS ngày sau, đổi giá trị này cho phù hợp.

## Kiểm tra kết quả

Chạy `stat -c '%U %G %a %n' /etc/aws-daily-lab/app.env`: mong đợi `root labapp 640`. Kiểm tra app user đọc được bằng `sudo -u labapp test -r /etc/aws-daily-lab/app.env`, chỉ kiểm tra exit code; không `cat` secrets ra terminal được ghi log. CA bundle có thể là 644 vì không chứa secret. File env nằm ngoài `/opt/aws-daily-lab`, nên không thể vô tình được `git add` từ repo.

## Lỗi thường gặp

Password chưa encode khiến URL parser đọc sai host hoặc port. Dùng private IP thay endpoint làm TLS hostname mismatch. File root 600 khiến app không đọc được; cấp group cụ thể thay vì mở quyền world-readable. `PUBLIC_BASE_URL` sai tạo short URL sai dù database và redirect nội bộ vẫn hoạt động.

## Dọn dẹp

Giữ file cho runtime và reboot. Khi secret lộ, đổi password RDS và cập nhật file trước khi restart app; chỉ xóa file khỏi Git không thu hồi secret đã lộ. Kết thúc lab, xóa đúng file secrets sau khi dừng app và quyết định dữ liệu nào cần giữ; CA công khai không cần được coi như password.
