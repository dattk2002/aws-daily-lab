# Target group đi qua Nginx

## Mục tiêu
Tạo target group tên riêng cho lab, đăng ký EC2 hiện có và kiểm tra đích thực sự là Nginx. Dùng VPC cùng EC2; app gốc nằm ở `/opt/aws-daily-lab/labs/url-shortener`, Node nghe `127.0.0.1:3000`, Nginx nghe 80.
## Hiểu nhanh
Target group mô tả kiểu target, protocol, port và health check. Listener chưa có nên target có thể báo `unused`: đó khác với ứng dụng chết. Chọn target type `instance` giúp ALB dùng địa chỉ private chính của EC2. Cổng 80 ở đây là backend HTTP; frontend có thể là 80 hoặc HTTPS 443 về sau. Chuyển target port thành 3000 sẽ bỏ qua Nginx và không hoạt động khi Node chỉ bind loopback.
Phép thử trên EC2 phải thành công trước khi xét SG. Health check ALB thường dùng Host header dựa trên địa chỉ IP của target, vì vậy Nginx phải có server block/default phù hợp, không chỉ nhận đúng domain trình duyệt. Không mở Node ra `0.0.0.0` để chữa lỗi định tuyến.
## Thực hành
Các lệnh AWS CLI dưới đây chạy trong shell máy cá nhân với profile `lab` đã cấu hình ở 02-5. Mỗi khi mở shell mới, đặt lại `export AWS_PROFILE=lab`, khôi phục các biến ID/Region từ sổ lab và kiểm tra identity trước mutation. Không đặt profile cá nhân này trên EC2 hoặc trong cấu hình CloudWatch agent; các tiến trình đó dùng instance role.

Các lệnh tạo cloud chỉ là ví dụ học tập, người học phải chủ động chạy sau khi kiểm tra tài khoản. Trong shell AWS CLI, điền các ID từ ngày trước:
```bash
export AWS_PROFILE=lab
export LAB_VPC_ID=vpc-REPLACE
export LAB_INSTANCE_ID=i-REPLACE
export LAB_TG_ARN=$(aws elbv2 create-target-group \
  --name aws-daily-lab-tg --protocol HTTP --port 80 \
  --target-type instance --vpc-id "$LAB_VPC_ID" \
  --health-check-path /ready --matcher HttpCode=200 \
  --health-check-interval-seconds 15 \
  --health-check-timeout-seconds 5 \
  --healthy-threshold-count 2 --unhealthy-threshold-count 2 \
  --query TargetGroups[0].TargetGroupArn --output text)
aws elbv2 register-targets --target-group-arn "$LAB_TG_ARN" \
  --targets "Id=$LAB_INSTANCE_ID,Port=80"
aws elbv2 describe-target-health --target-group-arn "$LAB_TG_ARN"
```
Tên cố định để dễ kiểm kê; nếu đã có group cùng tên, đọc cấu hình bằng `describe-target-groups --names aws-daily-lab-tg` trước, không tạo thêm tên ngẫu nhiên. Ghi ARN vào sổ lab không chứa secrets. Trên EC2, chạy riêng:
```bash
curl -i --max-time 5 http://127.0.0.1:3000/health
curl -i --max-time 5 http://127.0.0.1/ready
sudo nginx -t
```
Lệnh đầu xác nhận Node sống, lệnh hai kiểm tra cả Nginx và DB. Nếu endpoint thứ hai 503, xử lý DB trước khi chờ ALB chữa hộ. Bài tiếp theo giải thích quyết định dùng `/ready`.
## Kiểm tra kết quả
Ghi protocol HTTP, port 80, target type instance, VPC ID và target ID. Khi chưa gắn listener, `Target.NotInUse` là kết quả có thể chấp nhận; chưa được gọi đây là end-to-end thành công. Sau bài 09-4 group phải có target `healthy`. Tại EC2, `/health` trả 200 với JSON `{"status":"ok"}`; `/ready` chỉ 200 khi truy vấn DB thành công.
## Lỗi thường gặp
Đăng ký instance khác Region hoặc VPC không thể tạo đường mạng mong muốn. `Target.ResponseCodeMismatch` là HTTP trả khác matcher; đừng đổi matcher thành 200–499 để che 503. `Target.Timeout` cần kiểm tra SG, port, route và Nginx. Không xem lỗi `unused` như timeout, vì target chưa được listener sử dụng có nguyên nhân cấu hình khác.
## Dọn dẹp
Giữ target group và instance cho ALB. Nếu bỏ bài trước khi gắn listener, deregister đúng instance rồi xóa đúng ARN bằng `aws elbv2 delete-target-group --target-group-arn "$LAB_TG_ARN"`. Nếu ARN đang được listener tham chiếu phải tháo tham chiếu trước. Target group không làm EC2/RDS ngừng tính phí; theo dõi toàn bộ tài nguyên đang chạy.
