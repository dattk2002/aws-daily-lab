# CloudWatch agent thu log và memory

## Mục tiêu
Đưa đúng access/error logs Nginx và memory metric lên CloudWatch bằng agent. Dùng EC2 AL2023, instance profile giữ các quyền SSM hiện có và thêm quyền CloudWatch cần thiết; không tạo access key dài hạn. Logs, metrics tùy chỉnh và ingestion có thể tính phí.
## Hiểu nhanh
Agent đọc file trên EC2 rồi gửi qua HTTPS tới dịch vụ AWS. Nó cần cả quyền đọc file cục bộ, IAM và đường mạng đi tới endpoint; SG inbound 80 không cấp quyền gửi log. Với EC2 private, cần egress qua hạ tầng đã chuẩn bị hoặc VPC endpoints tương ứng; không thêm NAT Gateway mặc định chỉ để qua bài mà không xem chi phí.
Bài dùng `CloudWatchAgentServerPolicy` làm điểm xuất phát lab theo tài liệu AWS, gắn vào **role hiện có**, không thay instance profile làm mất SSM. Khi dùng lâu dài, thu hẹp quyền Logs về log group lab; `PutMetricData` giới hạn namespace qua condition khi phù hợp. Log group retention do người triển khai đặt để agent không cần thêm quyền sửa retention.
## Thực hành
Các lệnh AWS CLI dưới đây chạy trong shell máy cá nhân với profile `lab` đã cấu hình ở 02-5. Mỗi khi mở shell mới, đặt lại `export AWS_PROFILE=lab`, khôi phục các biến ID/Region từ sổ lab và kiểm tra identity trước mutation. Không đặt profile cá nhân này trên EC2 hoặc trong cấu hình CloudWatch agent; các tiến trình đó dùng instance role.

Trong IAM Console, kiểm tra role của EC2 và thêm policy agent có chủ đích. Từ CLI người học có quyền Logs, tạo hai log groups nếu chưa tồn tại và đặt retention 7 ngày:
```bash
export AWS_PROFILE=lab
aws logs create-log-group --log-group-name /aws-daily-lab/nginx-access
aws logs create-log-group --log-group-name /aws-daily-lab/nginx-error
aws logs put-retention-policy --log-group-name /aws-daily-lab/nginx-access --retention-in-days 7
aws logs put-retention-policy --log-group-name /aws-daily-lab/nginx-error --retention-in-days 7
```
Nếu `ResourceAlreadyExistsException`, inspect group hiện hữu rồi chỉ đặt retention cho group lab; không tạo lại với tên khác. Trên EC2 cài agent và ghi file cấu hình riêng:
```bash
sudo dnf install -y amazon-cloudwatch-agent
sudo tee /opt/aws/amazon-cloudwatch-agent/etc/lab.json >/dev/null <<'JSON'
{
  "agent": {"metrics_collection_interval": 60},
  "metrics": {
    "namespace": "CWAgent",
    "append_dimensions": {"InstanceId": "${aws:InstanceId}"},
    "metrics_collected": {"mem": {"measurement": ["mem_used_percent"]}}
  },
  "logs": {"logs_collected": {"files": {"collect_list": [
    {"file_path": "/var/log/nginx/aws-daily-lab-access.jsonl", "log_group_name": "/aws-daily-lab/nginx-access", "log_stream_name": "{instance_id}"},
    {"file_path": "/var/log/nginx/aws-daily-lab.error.log", "log_group_name": "/aws-daily-lab/nginx-error", "log_stream_name": "{instance_id}"}
  ]}}}
}
JSON
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl \
  -a fetch-config -m ec2 \
  -c file:/opt/aws/amazon-cloudwatch-agent/etc/lab.json -s
```
Heredoc có dấu nháy giữ nguyên `${aws:InstanceId}` cho agent, không để shell expand. Agent có thể chạy root để đọc system logs theo cấu hình mặc định; điều đó không đổi user chạy Node app. Gọi `/health` qua ALB sau khi agent bắt đầu, rồi xem status bằng cùng ctl với `-a status`.
## Kiểm tra kết quả
Trong CloudWatch Logs đúng Region, stream có InstanceId chứa request vừa tạo, path/status parse được. Với error log chưa có event, stream trống chưa đủ chứng minh agent lỗi; tạo sự cố có kiểm soát ở bài 11-5. Trong Metrics, namespace CWAgent có mem_used_percent của đúng InstanceId sau vài chu kỳ. `agent running` một mình chưa chứng minh dữ liệu đã tới AWS.
## Lỗi thường gặp
AccessDenied thường là role/policy, timeout là network/endpoint, file not found là path chưa phát log. Xem `/opt/aws/amazon-cloudwatch-agent/logs/amazon-cloudwatch-agent.log` và `configuration-validation.log` cục bộ. Agent không tự biết PM2 logs của app user; bài này chủ đích chỉ thu hai file Nginx, không hứa đã thu mọi log ứng dụng.
## Dọn dẹp
Giữ agent và log groups 7 ngày cho capstone. Khi không dùng: `sudo systemctl stop amazon-cloudwatch-agent`, disable dịch vụ nếu không muốn reboot tự chạy, rồi xóa đúng hai group lab sau khi xuất bằng chứng. Xóa group khi agent còn chạy có thể khiến nó tạo lại nếu có quyền. Tháo policy thêm cho lab khi không role nào còn cần, giữ quyền SSM và quyền khác đã có.
