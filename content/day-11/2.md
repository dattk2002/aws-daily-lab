# Log có cấu trúc tại Nginx

## Mục tiêu
Tạo access log JSON một dòng mỗi request, có request ID và thời gian upstream để phục vụ truy tìm lỗi. Bài chỉnh Nginx trên EC2 lab; không yêu cầu thay mã demo hoặc giả định demo đã instrument distributed tracing.
## Hiểu nhanh
Một log tốt trả lời khi nào, ở đâu, request nào và kết quả gì. JSON giúp query status bằng số thay vì grep chuỗi tùy ý. Nginx `$request_id` là ID tại proxy; header `X-Amzn-Trace-Id` đi từ ALB có thể ghi để liên hệ request nhưng bản thân nó chưa tạo distributed trace. Không tuyên bố có X-Ray chỉ vì log một header.
Không log body `POST /shorten`, Authorization, cookies, DATABASE_URL hoặc URL đích đầy query nhạy cảm. `$uri` thay cho `$request_uri` bỏ query, nhưng path vẫn có thể chứa dữ liệu người dùng, nên chỉ thử với code và URL công khai của lab. SG ngày 9 giới hạn nguồn ALB giúp giảm nguồn có thể đưa header vào Nginx; vẫn xem mọi trường client là dữ liệu không tin cậy và escape JSON.
## Thực hành
Trên EC2 tạo file log format trong ngữ cảnh `http`; với AL2023, các file `conf.d/*.conf` được include tại `http`, hãy kiểm tra `sudo nginx -T` cục bộ trước, không đăng toàn output nếu có secrets. Sao lưu file server block lab để khôi phục rồi tạo format riêng:
```bash
sudo tee /etc/nginx/conf.d/lab-log-format.conf >/dev/null <<'NGINX'
log_format lab_json escape=json
  '{"timestamp":"$time_iso8601","request_id":"$request_id",'
  '"trace_id":"$http_x_amzn_trace_id","method":"$request_method",'
  '"path":"$uri","status":$status,"duration":$request_time,'
  '"upstream_status":"$upstream_status",'
  '"upstream_duration":"$upstream_response_time"}';
NGINX
```
Trong **server block app đang dùng** ở `/etc/nginx/conf.d/url-shortener.conf`, thay/chọn `access_log` thành đúng dòng sau, không dán server block thứ hai:
```nginx
access_log /var/log/nginx/aws-daily-lab-access.jsonl lab_json;
```
Format file cần được include trước file sử dụng; tên `lab-log-format.conf` đứng trước `url-shortener.conf`. Giữ proxy về `127.0.0.1:3000` như cấu hình gốc. Kiểm tra rồi reload:
```bash
sudo nginx -t
sudo systemctl reload nginx
curl -sS --max-time 10 http://127.0.0.1/health
sudo tail -n 1 /var/log/nginx/aws-daily-lab-access.jsonl \
  | python3 -c 'import json,sys; x=json.load(sys.stdin); print(x["status"], x["path"], x["request_id"])'
```
Từ laptop gọi thêm `/ready` qua ALB để có trace header; request local có thể có trace_id rỗng và điều đó hợp lệ. Chỉ dùng reload sau `nginx -t` thành công.
## Kiểm tra kết quả
Mỗi dòng parse được bằng JSON, status là số, path là `/health` hoặc `/ready`, duration có giá trị và request_id không rỗng. Một request ALB tới Nginx có thể được liên hệ bằng trace_id nếu header hiện diện; chưa có span DB hoặc app trace nên không tự vẽ timeline distributed. Kiểm tra log không chứa query/body/password của các phép thử.
## Lỗi thường gặp
Đặt `log_format` trong `server` hoặc `location` gây lỗi context. File format include sau file server gây unknown log format. Một request đi vào server mặc định khác sẽ không dùng access_log vừa chỉnh; kiểm tra server_name/default và Host. `upstream_status` có thể là `-` hoặc nhiều giá trị nên giữ dạng chuỗi, không ép số làm JSON lỗi.
## Dọn dẹp
Giữ file JSON log cho agent bài sau. Cấu hình logrotate cho file riêng hoặc theo dõi dung lượng; đừng để log lớn lấp EBS. Nếu hoàn nguyên, gỡ dòng dùng `lab_json` trước khi gỡ file định nghĩa, chạy `nginx -t` và reload. Không xóa error log đang cần chẩn đoán. Lưu trữ EBS và CloudWatch sau này có chi phí theo dung lượng.
