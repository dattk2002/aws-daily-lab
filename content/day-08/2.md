# Cấu hình Nginx tới upstream loopback

## Mục tiêu

Cài Nginx trên AL2023, dùng mẫu `labs/nginx/url-shortener.conf`, kiểm tra syntax trước reload và truy cập health qua port 80. Không mở Node 3000 ra Internet.

## Hiểu nhanh

Nginx đọc cấu hình chính và các file được include. Package trên các hệ điều hành có thể đặt default server ở vị trí khác nhau; không mặc định mọi máy đều có `sites-enabled`. `nginx -t` kiểm tra syntax và file cần mở, còn request thật kiểm tra server block nào được chọn và upstream có hoạt động không.

Bạn cần app ngày 07 online trên `127.0.0.1:3000`, quyền sudo của `ec2-user`, và source repository tại `/opt/aws-daily-lab`. User app không cần sở hữu `/etc/nginx`. Chỉ dùng HTTP cho dữ liệu thử công khai trong ngày này; mở 80 từ IP công cộng của bạn `/32` là đủ để thử trực tiếp, không cần Anywhere. IP nguồn quản trị và nguồn browser có thể khác nếu đang dùng VPN.

## Thực hành

Trong phiên quản trị EC2:

```bash
sudo dnf install -y nginx
sudo nginx -T
sudo install -o root -g root -m 644 \
  /opt/aws-daily-lab/labs/nginx/url-shortener.conf \
  /etc/nginx/conf.d/url-shortener.conf
sudo nginx -t
```

Trước khi copy, đọc mẫu và cấu hình hiện hành. Nếu có server mặc định trùng `default_server` hoặc bắt mọi request, sao lưu file cấu hình liên quan rồi vô hiệu hóa riêng server mặc định không dùng của lab. Không xóa toàn bộ nginx.conf vì còn khối `events`, `http` và include cần thiết. Dùng `sudoedit` cho chỉnh sửa hệ thống, rồi chạy lại `nginx -t` tới khi hợp lệ.

Sau syntax check thành công:

```bash
sudo systemctl enable --now nginx
sudo systemctl reload nginx
curl -i -H 'Host: lab.invalid' http://127.0.0.1/health
sudo ss -lntp 'sport = :80 or sport = :3000'
```

Trong SG app, thêm HTTP 80 từ IP browser của bạn `/32`. Từ laptop chạy `curl -i http://<EC2_PUBLIC_IP>/health`. Chỉ sửa SG thuộc máy lab và kiểm tra public IPv4/route nếu timeout. Không cần cho inbound 5432 hoặc 3000.

## Kiểm tra kết quả

Syntax test thành công, service active, HTTP qua 80 trả health JSON của demo. Socket 80 thuộc Nginx, socket 3000 chỉ ở loopback thuộc app. Nếu nhìn thấy welcome page, request chưa vào server block demo; kiểm tra `listen`, `server_name` và default selection thay vì đổi code Node. Gọi `/ready` qua proxy phải trả 200 trước khi thử tạo link từ laptop.

## Lỗi thường gặp

Duplicate default server: còn hai khai báo default trên cùng địa chỉ/port. 502: Nginx đã nhận request nhưng upstream không đáp ứng hợp lệ, kiểm tra Node trực tiếp. Timeout bên ngoài khi loopback 80 tốt: tập trung SG, route, public IP hoặc firewall hệ điều hành; không mở port 3000 để né.

## Dọn dẹp

Giữ Nginx, rule 80 giới hạn và app cho bài tiếp theo. Nếu chỉ tháo proxy, dừng/disable Nginx, gỡ đúng file `/etc/nginx/conf.d/url-shortener.conf` sau khi sao lưu khi cần, khôi phục default block đã đổi và xóa rule 80 của lab. Muốn ngừng chi phí phải dọn EC2/RDS cùng các đĩa/backup còn lại.
