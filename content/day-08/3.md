# Headers và timeout phải phản ánh đúng tuyến mạng

## Mục tiêu

Đọc và cấu hình các header chuyển tiếp cần thiết, đặt timeout hữu hạn cho upstream và kiểm tra redirect giữ đúng URL đích. Hiểu giới hạn tin cậy của `X-Forwarded-For` trước khi đặt thêm ALB ở ngày sau.

## Hiểu nhanh

Khi Nginx gọi Node, TCP peer của Node là loopback; header có thể mang thông tin request gốc. `Host` giữ host bên ngoài; `X-Forwarded-Proto` diễn đạt giao thức client dùng tới proxy; `X-Forwarded-For` có thể mang chuỗi IP. Client có thể tự gửi header giả, nên chúng không tự là danh tính đáng tin để cấp quyền. Demo vẫn lấy short URL từ `PUBLIC_BASE_URL`, không tự thay đổi base URL theo header bất kỳ.

Timeout không chỉ là một “thời gian chờ chung”. Connect timeout giới hạn giai đoạn mở kết nối upstream; read timeout đo khoảng im lặng giữa các lần đọc response, không nhất thiết là deadline tổng cho request. Đặt quá dài che app treo và giữ tài nguyên; quá ngắn làm request hợp lệ thất bại. Với demo ngắn, bắt đầu nhỏ rồi đo thay vì đặt hàng giờ.

## Thực hành

Trong `/etc/nginx/conf.d/url-shortener.conf`, tìm location đang proxy toàn bộ URI. Đối chiếu đoạn dưới và giữ một bộ directive duy nhất thay vì dán thêm bản trùng:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 3s;
    proxy_read_timeout 10s;
    proxy_send_timeout 10s;
}
```

`proxy_pass` không thêm URI mới nên route `/r/:code` của demo được giữ nguyên. Các biến `$...` là biến Nginx; khi tạo file bằng shell phải dùng heredoc quoted hoặc editor để shell không thay chúng. Chạy `sudo nginx -t` rồi mới `sudo systemctl reload nginx`.

Từ laptop POST `/shorten` với `https://example.com`, lấy code rồi `curl -i http://<EC2_PUBLIC_IP>/r/<CODE>`. Kiểm tra status 302 và Location; đừng dùng `curl -I` vì demo cam kết GET, không cam kết HEAD. Đối chiếu shortUrl với PUBLIC_BASE_URL ngoài file secret mà không in cả file.

## Kiểm tra kết quả

Health/ready vẫn 200, request tạo link vẫn 201 và redirect Location không bị biến thành loopback hoặc mất `/r/`. Viết một câu chỉ ra vì sao header giả không được dùng như thông tin đăng nhập. Khi thêm ALB terminate TLS ngày sau, Nginx nhìn thấy HTTP từ ALB nên `$scheme` có thể là http; phải thiết kế lại việc tin header từ ALB và giới hạn nguồn SG, không mù quáng copy cấu hình hôm nay.

## Lỗi thường gặp

Đổi `proxy_pass` kèm URI có thể thay phần đường dẫn và tạo 404 khó hiểu. Một client timeout trước không nhất thiết do Nginx timeout; còn có DNS, browser, app và DB. Tăng read timeout không sửa được lỗi TLS database. Dùng X-Forwarded-For đầu tiên làm IP đáng tin khi chưa có trust boundary có thể chấp nhận dữ liệu client tự bịa.

## Dọn dẹp

Giữ các giá trị đã kiểm tra, bỏ thử nghiệm timeout cực dài hoặc header chứa dữ liệu debug. Xóa bản ghi test theo code nếu không cần. Không ghi request Authorization hoặc database URL vào response header. Bài này không tạo dịch vụ mới; EC2/RDS hiện có vẫn mang chi phí.
