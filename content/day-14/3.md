# Logical dump của PostgreSQL

## Mục tiêu

Tạo archive `pg_dump` của database demo và manifest SHA-256, rồi kiểm tra danh mục archive trước khi đưa lên S3. Phương pháp này phục vụ bài restore ở mức database, không thay thế toàn bộ cấu hình RDS.

## Hiểu nhanh

Logical dump diễn tả schema và dữ liệu bằng cấu trúc PostgreSQL. Custom format `-Fc` dùng `pg_restore`; plain SQL dùng `psql`. File dump không tự mang theo network, IAM, parameter groups hay mọi global role của cluster. Chọn client cùng major với server để đơn giản; `pg_dump` cũ hơn major server có thể từ chối. Dữ liệu backup nhạy cảm như dữ liệu gốc dù tên file trông vô hại.

## Thực hành

Chạy trên EC2 trong mạng có đường tới RDS private, có client PostgreSQL tương thích và đủ dung lượng. Dùng database account chỉ đọc cần thiết để dump; với demo nhỏ có thể dùng chủ schema lab. Nguồn local cũng dùng được nếu bạn chưa giữ RDS, nhưng ghi rõ đó là local drill. Dùng file password ngoài Git với mode 600 hoặc cơ chế secret hiện có; không đưa mật khẩu vào lệnh, URL in ra terminal hay history.

```bash
umask 077
mkdir -p ~/aws-daily-backup
cd ~/aws-daily-backup
export PGHOST='THAY-ENDPOINT-RDS-LAB'
export PGPORT=5432
export PGUSER='THAY-USER-LAB'
export PGDATABASE='THAY-DATABASE-LAB'
export PGSSLMODE=verify-full
export PGSSLROOTCERT='/DUONG-DAN/CA-RDS.pem'
export PGPASSFILE="$HOME/.pgpass-aws-daily-lab"
pg_dump --version
psql -X -v ON_ERROR_STOP=1 -c 'SELECT version();'
pg_dump --format=custom --no-owner --no-acl --file=links-day14.dump
pg_restore --list links-day14.dump > links-day14.contents.txt
sha256sum links-day14.dump > links-day14.dump.sha256
```

Điền `.pgpass` bằng trình soạn thảo an toàn theo định dạng PostgreSQL `host:port:database:user:password`, không dùng echo mật khẩu. Trên macOS có thể dùng `shasum -a 256` thay `sha256sum`; dùng cùng công cụ khi kiểm tra. Ghi số hàng và một code mẫu vào manifest riêng trước dump trong lúc lab không có người ghi, để bài sau so sánh có ý nghĩa.

## Kiểm tra kết quả

`pg_dump` và `pg_restore --list` exit 0, file khác 0 byte, danh mục có bảng `public.links` và dữ liệu của nó. Chạy `sha256sum -c links-day14.dump.sha256` phải báo OK. Kiểm tra này chỉ chứng minh file không đổi và đọc được header, chưa chứng minh restore thành công. Với hệ thống đang ghi liên tục, count chụp ngoài transaction dump không nhất thiết khớp; lab nên tạm ngừng tạo link trong vài phút thử nghiệm và ghi rõ giả định.

## Lỗi thường gặp

Thiếu SELECT hoặc quyền schema gây dump lỗi; không bỏ qua stderr. Không dùng `--no-verify` hay `sslmode=disable` để vượt lỗi CA của RDS. `pg_restore` không đọc plain SQL; đuôi `.dump` không quyết định format. Dump chỉ bảng links có thể bỏ phụ thuộc; bài này dump toàn database demo để tránh tự tạo tập không đầy đủ.

## Dọn dẹp

Giữ archive, checksum và ghi chú đối chiếu cho hai bài tiếp theo. Không commit chúng vì chứa dữ liệu. Local files không có phí AWS riêng nhưng EC2 disk và thời gian DB hoạt động vẫn có phí; theo dõi dung lượng để không đầy ổ. Hết lab, xóa đúng file backup local theo quy định dữ liệu và bỏ file password thử nếu không còn cần, không xóa credentials dùng chung.
