# Lưu bản dump riêng trên S3

## Mục tiêu

Upload archive logical dump vào prefix backup riêng với timestamp, tải về và đối chiếu checksum. Nêu rõ khác biệt giữa file dump tự tạo và chức năng RDS snapshot export.

## Hiểu nhanh

S3 là nơi giữ bytes; khả năng phục hồi phụ thuộc format và công cụ tạo file. RDS snapshot export đưa dữ liệu ra định dạng phục vụ phân tích, không tạo file mà `restore-db-instance-from-db-snapshot` có thể dùng, cũng không phải input trực tiếp của `pg_restore`. Bài này upload chính archive `pg_dump -Fc`. Prefix `backups/` không nằm trong lifecycle `scratch/` bảy ngày. Lưu trữ, API, retrieval hoặc KMS tùy cấu hình đều có thể tính phí.

## Thực hành

Cần archive và checksum bài trước, bucket private ngày 13. Dùng backup operator hoặc role riêng có `s3:PutObject`/`GetObject` chỉ `arn:aws:s3:::TEN-BUCKET/backups/day14/*`. Runtime role ngày 13 chỉ có `scratch/*` nên bị từ chối là đúng; đừng mở cả bucket cho web server. Nếu tải bằng instance, cấp quyền prefix backup có chủ ý cho role phục vụ nhiệm vụ backup và tháo sau; không chép access key vào EC2.

```bash
cd ~/aws-daily-backup
export LAB_BUCKET='THAY-BUCKET-LAB'
export BACKUP_KEY="backups/day14/$(date -u +%Y%m%dT%H%M%SZ)-links.dump"
aws s3 cp links-day14.dump "s3://$LAB_BUCKET/$BACKUP_KEY" \
  --sse AES256 --only-show-errors
aws s3 cp links-day14.dump.sha256 "s3://$LAB_BUCKET/$BACKUP_KEY.sha256" \
  --sse AES256 --only-show-errors
aws s3api head-object --bucket "$LAB_BUCKET" --key "$BACKUP_KEY" \
  --query '{Size:ContentLength,Encryption:ServerSideEncryption}'
mkdir -p downloaded
aws s3 cp "s3://$LAB_BUCKET/$BACKUP_KEY" downloaded/links-day14.dump \
  --only-show-errors
aws s3 cp "s3://$LAB_BUCKET/$BACKUP_KEY.sha256" downloaded/links-day14.dump.sha256 \
  --only-show-errors
(cd downloaded && sha256sum -c links-day14.dump.sha256)
```

Giữ nguyên tên local mà checksum tham chiếu. `AES256` yêu cầu mã hóa SSE-S3; nếu bucket yêu cầu customer-managed KMS key, thay theo chính sách đã duyệt và cấp KMS cho đúng hai danh tính đọc/ghi, không tắt yêu cầu mã hóa để upload. Ghi `BACKUP_KEY` chính xác để phục hồi; không dùng listing “file mới nhất” khi cần bằng chứng cụ thể.

## Kiểm tra kết quả

Đối chiếu `Size` với file local, encryption theo yêu cầu và checksum báo OK sau round trip. Dùng browser không đăng nhập hoặc request không ký vào object chỉ là phép thử truy cập; không public object để tiện tải. Viết một câu trong runbook: “Đây là custom archive của pg_dump; restore bằng pg_restore vào database riêng.” Câu này tránh người sau chọn nhầm nút RDS snapshot restore.

## Lỗi thường gặp

Lấy nhầm checksum cũ làm file hợp lệ bị báo mismatch; không sửa checksum cho khớp một file chưa xác định nguồn. Key trùng có thể ghi đè khi không versioning; dùng timestamp duy nhất và ghi identity/giờ tạo. Checksum cùng chỗ không chống người tấn công sửa cả hai, nhưng hữu ích phát hiện lỗi vận chuyển trong lab.

## Dọn dẹp

Giữ hai object đúng key cho bài restore. Sau diễn tập, dùng operator xóa từng key bằng `s3api delete-object`; kiểm tra versioning trước khi kết luận bytes đã được dọn. Không áp lifecycle ngắn vào backup chỉ vì dữ liệu thử nhỏ; chọn retention theo RPO, yêu cầu pháp lý và kế hoạch phục hồi. Giữ bucket nếu còn bài CD dùng artifact nhưng tách prefix và quyền.
