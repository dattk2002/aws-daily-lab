# Restore thử và chứng minh dữ liệu

## Mục tiêu

Phục hồi archive đã tải từ S3 vào database thử riêng, đối chiếu dữ liệu và gọi API với database đó. Không chạy restore đè database nguồn. Đo thời gian thực tế làm căn cứ đánh giá RTO đề xuất.

## Hiểu nhanh

Backup có giá trị khi dựng lại được trạng thái cần thiết. Restore thành công về mặt exit code vẫn cần kiểm tra ý nghĩa: links có code cũ, URL đúng, redirect không hỏng. Database đích cần role, quyền tạo schema và extension tương thích. Vì bài dùng `--no-owner --no-acl`, người restore sở hữu object; production phải có kế hoạch quyền rõ hơn. Một database cùng instance không kiểm tra được mọi sự cố mất toàn RDS, nhưng là drill logical restore hợp lý với lab nhỏ.

## Thực hành

Dùng EC2 có TLS tới RDS private hoặc PostgreSQL local của lab; ghi môi trường đã chọn. Cần quyền `CREATEDB` của operator. Giữ các biến kết nối an toàn ở bài trước, thay `PGDATABASE=postgres` khi tạo database mới. `.pgpass` phải có dòng phù hợp database đích, mode 600, không in ra log.

```bash
cd ~/aws-daily-backup/downloaded
sha256sum -c links-day14.dump.sha256
export PGDATABASE=postgres
psql -X -v ON_ERROR_STOP=1 -c 'CREATE DATABASE aws_daily_restore;'
export PGDATABASE=aws_daily_restore
pg_restore --exit-on-error --single-transaction \
  --no-owner --no-acl --dbname="$PGDATABASE" links-day14.dump
psql -X -v ON_ERROR_STOP=1 -c 'SELECT count(*) FROM links;'
psql -X -v ON_ERROR_STOP=1 \
  -c 'SELECT code, url FROM links ORDER BY created_at, code LIMIT 5;'
```

Nếu `aws_daily_restore` đã tồn tại, dừng kiểm tra, không thêm `--clean` tự động. DB mới phải rỗng. Dùng cùng script service của tuyến chính nhưng một process tạm ở port 3001, trỏ `DATABASE_URL` tới database đích qua file môi trường private hiện có; dùng TLS CA với `PGSSLROOTCERT` như demo yêu cầu. Không sửa cấu hình process production. Đặt `PUBLIC_BASE_URL=http://127.0.0.1:3001` và chỉ bind `HOST=127.0.0.1`.

## Kiểm tra kết quả

`GET /ready` của process thử phải trả 200; gọi `GET /r/CODE-DA-GHI-TRUOC-BACKUP` với curl không follow redirect phải thấy 302 và Location đúng URL trong manifest. Tạo một link mới bằng `POST /shorten` với JSON `{ "url": "https://example.com" }`, mong đợi 201 và `code`, `shortUrl`. So sánh count của dữ liệu cũ trước khi tạo link thử mới. Ghi tổng phút từ bắt đầu tải backup tới API hoạt động, cùng phần việc thao tác tay; không coi đó là SLA.

## Lỗi thường gặp

Chạy `npm run db:init` trước restore có thể tạo bảng trùng; archive đầy đủ đã có schema. `relation already exists` là dấu hiệu đích không rỗng. `GET /health` vẫn trả `{ "status": "ok" }` khi DB lỗi vì đây là liveness; phải dùng `/ready` và endpoint có dữ liệu. TLS lỗi không được chữa bằng bỏ xác minh certificate.

## Dọn dẹp

Dừng process thử port 3001. Sau khi xác nhận đúng database đích, đổi `PGDATABASE=postgres` và chạy `psql -X -v ON_ERROR_STOP=1 -c 'DROP DATABASE aws_daily_restore;'`. Không dùng tên DB nguồn. Dọn archive và hai object S3 đúng key khi hết retention lab, tháo quyền backup tạm nếu đã thêm. Nếu đã tạo instance restore ở bài 2, kiểm tra riêng việc xóa instance đó; drop database không làm RDS ngừng tính phí.
