# Chuẩn bị EC2 và bộ cài release qua SSM

## Mục tiêu

Chuẩn bị một EC2 Amazon Linux 2023 có SSM online và cài helper deploy đã review. Lab deploy một máy, có gián đoạn ngắn khi restart; không mô tả thành blue/green hoặc zero downtime. Phần này chưa chạy release vì secret và document sẽ được chuẩn bị ở bài sau.

## Hiểu nhanh

Run Command truyền ý định tới SSM Agent; EC2 tự tải artifact từ S3. Runner không SSH vào máy, không cần mở inbound 22. Cần đầy đủ: instance role, agent, đường mạng, Node 22/npm/PM2, AWS CLI v2, user không root, DB private có TLS, CA RDS và artifact đúng cấu trúc. Chỉ có quyền SendCommand không tự tạo các điều kiện đó.

## Thực hành

Giữ hoặc dựng lại có chủ ý EC2/RDS từ tuyến chính theo các bài trước. Instance role có trust EC2, `AmazonSSMManagedInstanceCore` cho lab và policy `s3:GetObject` chỉ `arn:aws:s3:::BUCKET_LAB/releases/*`; bài 3 thêm parameter/KMS. Giữ quyền CloudWatch đã có. Xác nhận agent đủ mới hỗ trợ `interpolationType: ENV_VAR` (ít nhất 3.3.2746.0), `sudo systemctl status amazon-ssm-agent`, Node 22, npm, PM2 và CLI chạy được với user app.

Mạng cần outbound HTTPS/DNS tới SSM và `ssmmessages` (cùng `ec2messages` nếu Region/agent yêu cầu), S3 và npm registry. Có thể dùng NAT/internet route hợp lệ hoặc interface endpoints SSM cùng S3 endpoint; endpoint SG cần inbound 443 từ SG EC2 và private DNS. Chỉ SSM endpoints không cho phép `npm ci` tải Internet; nếu máy không có egress registry, phải chuẩn bị kho dependency hoặc artifact runtime cho đúng Linux/kiến trúc thay cho lab này. EC2 tới RDS private port 5432 được SG nguồn tham chiếu và TLS verify-full. ALB/Nginx giữ nguyên tuyến chính.

Dùng lại user `labapp`, PM2 `/home/labapp/.local/bin/pm2`, wrapper `/home/labapp/bin/start-app.sh`, file `/etc/aws-daily-lab/app.env` root:labapp 640 và CA `/etc/aws-daily-lab/global-bundle.pem` đã chuẩn bị ngày 7. Không tạo user mới hoặc daemon PM2 khác. Nếu đã teardown, hoàn thành lại ngày 5–7 trước bài này. Xác nhận wrapper source file môi trường rồi `cd /opt/aws-daily-lab/labs/url-shortener` và `exec /usr/bin/npm start`, cùng startup service `pm2-labapp` đã được kiểm chứng reboot.

Chuẩn bị thư mục release và chuyển app hiện tại thành bootstrap **một lần**, sau khi đọc đường dẫn và xác nhận chưa có cấu trúc release. Các lệnh không xóa mã cũ; nếu đường dẫn đích đã tồn tại thì dừng kiểm tra:

```bash
sudo install -d -o labapp -g labapp -m 750 \
  /opt/aws-daily-lab/releases /opt/aws-daily-lab/shared
test ! -e /opt/aws-daily-lab/releases/bootstrap-day07
test ! -e /opt/aws-daily-lab/current
sudo -u labapp mv /opt/aws-daily-lab/labs/url-shortener \
  /opt/aws-daily-lab/releases/bootstrap-day07
sudo -u labapp ln -s /opt/aws-daily-lab/releases/bootstrap-day07 /opt/aws-daily-lab/current
sudo -u labapp ln -s /opt/aws-daily-lab/current /opt/aws-daily-lab/labs/url-shortener
```

Process đang chạy vẫn giữ code cũ tới restart; kiểm tra wrapper qua app path mới trước deployment. `bootstrap-day07` giúp quay lại setup ban đầu bằng thao tác symlink đã review, nhưng chưa là release SHA có provenance. Muốn dùng rollback tự động theo SHA ở bài 5, cần ít nhất hai archive/release đã kiểm tra. Không tạo snapshot mới hoặc thay subnet chỉ để chuyển thư mục.

Lưu script sau thành `/usr/local/bin/aws-daily-lab-release`, owner root, mode 755. Thay bucket/Region cố định trước khi cài; không nhận bucket tùy ý từ workflow:

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
umask 077
export AWS_REGION=ap-southeast-1
export PATH=/usr/local/bin:/usr/bin:/bin
bucket='THAY-BUCKET-LAB'
root=/opt/aws-daily-lab
sha="${1:?Cần SHA}"
[[ "$sha" =~ ^[a-f0-9]{40}$ ]] || exit 2
if [[ "$(id -u)" == 0 ]]; then
  env_tmp="$(mktemp /etc/aws-daily-lab/.app-env-XXXXXX)"
  aws ssm get-parameter --name /aws-daily-lab/runtime-env \
    --with-decryption --query Parameter.Value --output text > "$env_tmp"
  chown root:labapp "$env_tmp"
  chmod 640 "$env_tmp"
  mv "$env_tmp" /etc/aws-daily-lab/app.env
  exec runuser -u labapp -- "$0" "$sha"
fi
[[ "$(id -un)" == labapp ]] || exit 4
pm2=/home/labapp/.local/bin/pm2
release="$root/releases/$sha"
exec 9>"$root/deploy.lock"
flock -n 9 || { echo 'Đang có release khác chạy'; exit 3; }
if [[ ! -d "$release" ]]; then
  stage="$(mktemp -d "$root/releases/.stage-XXXXXX")"
  aws s3 cp "s3://$bucket/releases/$sha.tar.gz" "$stage/$sha.tar.gz" --only-show-errors
  aws s3 cp "s3://$bucket/releases/$sha.tar.gz.sha256" "$stage/$sha.tar.gz.sha256" --only-show-errors
  (cd "$stage" && sha256sum -c "$sha.tar.gz.sha256")
  mkdir "$stage/app"
  tar -xzf "$stage/$sha.tar.gz" -C "$stage/app" --strip-components=2
  test -f "$stage/app/package-lock.json"
  (cd "$stage/app" && npm ci --omit=dev)
  printf '%s\n' "$sha" > "$stage/app/RELEASE_SHA"
  mv "$stage/app" "$release"
fi
if [[ -L "$root/current" ]]; then
  readlink -f "$root/current" > "$root/shared/previous-release"
fi
ln -sfn "$release" "$root/current.next"
mv -Tf "$root/current.next" "$root/current"
unset DATABASE_URL PORT HOST PUBLIC_BASE_URL PGSSLROOTCERT
if "$pm2" describe aws-daily-lab >/dev/null 2>&1; then
  "$pm2" delete aws-daily-lab
fi
"$pm2" start /home/labapp/bin/start-app.sh --name aws-daily-lab \
  --interpreter /bin/bash --cwd "$root/labs/url-shortener"
for attempt in {1..30}; do
  if curl --fail --silent --max-time 2 http://127.0.0.1:3000/ready >/dev/null; then
    "$pm2" save
    echo "Release $sha ready"
    exit 0
  fi
  sleep 1
done
echo "Release $sha chưa ready; cần rollback" >&2
exit 1
```

Archive ngày 15 có đường `labs/url-shortener/...`, nên strip hai thành phần. Không chạy `db:init` tự động trong deploy; schema phải có sẵn, bài chỉ deploy code không migration phá hủy. SSM gọi helper root-owned bằng root để ghi secrets vào /etc; helper tự hạ quyền qua runuser trước khi tải/cài/chạy code. Không cấp sudo cho app user và không chạy npm install bằng root. PATH của noninteractive user phải tìm thấy Node/npm/PM2/AWS CLI; dùng binary cài hệ thống hoặc đường dẫn cố định đã kiểm tra.

## Kiểm tra kết quả

Quản trị chạy `aws ssm describe-instance-information` để thấy đúng instance Online và agent version. Dùng `sudo -u labapp -H bash -c 'command -v node npm aws; /home/labapp/.local/bin/pm2 --version; node --version'`, đọc quyền thư mục, symlink app path, wrapper và script. Đảm bảo labapp sở hữu /opt/aws-daily-lab để helper tạo current/deploy.lock, nhưng không sở hữu /usr/local/bin/aws-daily-lab-release hoặc thư mục /etc/aws-daily-lab. Đây chỉ là kiểm tra prerequisite, không chứng minh deploy thành công. Script có checksum để phát hiện file đổi; quyền ghi S3 và review source mới là hàng rào chống archive độc hại.

## Lỗi thường gặp

Instance Online nhưng tải S3 timeout là đường mạng khác. `npm` không tìm thấy thường do Node chỉ cài trong interactive shell của ec2-user. Hai PM2 daemon khác user gây EADDRINUSE. Thiếu `flock`/curl/tar cần cài công cụ OS trước, không cài trong lúc release. `.stage-*` thất bại giữ lại để debug và có thể tốn disk.

## Dọn dẹp

Giữ hạ tầng và helper cho bài 3–5; không xóa current release đang chạy. SSM endpoint, NAT, EC2, RDS, S3 và logs đều có thể tính phí; chọn một phương án mạng rồi kiểm tra tài nguyên sau khi học. Khi dừng toàn bộ, teardown theo runbook tuyến chính, xóa đúng endpoint/NAT lab nếu đã tạo. Không xóa role hay VPC dùng chung. Helper mới không tự rollback; bài 5 thao tác release cũ rõ ràng.
