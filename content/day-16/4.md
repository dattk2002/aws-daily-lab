# Deploy thủ công có kiểm tra và smoke test

## Mục tiêu

Chạy một workflow deploy được bấm chủ động trên `main`: test với DB tạm, đóng gói đúng SHA, upload private S3 rồi gọi document SSM đã pin version. Xác minh app qua readiness và request người dùng trước khi ghi release thành công.

## Hiểu nhanh

Workflow này dành cho API trên EC2, không phải website học tĩnh. Đặt file riêng `.github/workflows/deploy-demo.yml`; không thêm OIDC/AWS quyền vào workflow GitHub Pages root. Đây là mẫu dành cho đúng hạ tầng ngày 16: một instance, không migration và helper đã cài. Nếu thiếu role, network, secret, artifact policy, agent hoặc CA, dừng tại prerequisite tương ứng. SSM trả CommandId mới chỉ nhận yêu cầu, chưa xác nhận app khỏe.

## Thực hành

Tạo repository variables không nhạy cảm: `AWS_REGION`, `AWS_DEPLOY_ROLE_ARN`, `LAB_ARTIFACT_BUCKET`, `LAB_INSTANCE_ID`. Trust phải đúng subject hiện hành bài 1. Bucket private có lifecycle không xóa `releases/` trước thời gian rollback. Workflow dưới tự chạy lại kiểm tra của chính SHA đang deploy, không tải artifact ngẫu nhiên từ pull request:

```yaml
name: Deploy demo through SSM
on:
  workflow_dispatch:
permissions:
  contents: read
  id-token: write
concurrency:
  group: deploy-demo-lab
  cancel-in-progress: false
jobs:
  deploy:
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    timeout-minutes: 25
    services:
      postgres:
        image: postgres:17-alpine
        env:
          POSTGRES_USER: lab
          POSTGRES_PASSWORD: lab
          POSTGRES_DB: lab
        ports: ['5432:5432']
        options: >-
          --health-cmd "pg_isready -U lab -d lab"
          --health-interval 5s --health-timeout 5s --health-retries 10
    env:
      AWS_REGION: ${{ vars.AWS_REGION }}
      LAB_BUCKET: ${{ vars.LAB_ARTIFACT_BUCKET }}
      INSTANCE_ID: ${{ vars.LAB_INSTANCE_ID }}
      RELEASE_SHA: ${{ github.sha }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - name: Check website and content
        run: |
          npm ci
          npm run check:content
          npm run typecheck
          npm test
          npm run build
      - name: Test demo with temporary PostgreSQL
        working-directory: labs/url-shortener
        env:
          DATABASE_URL: postgres://lab:lab@127.0.0.1:5432/lab
        run: |
          npm ci
          npm run db:init
          npm test
      - name: Pack tracked demo files
        run: |
          mkdir -p release
          git archive --format=tar.gz --output="release/$RELEASE_SHA.tar.gz" HEAD labs/url-shortener
          (cd release && sha256sum "$RELEASE_SHA.tar.gz" > "$RELEASE_SHA.tar.gz.sha256")
          tar -tzf "release/$RELEASE_SHA.tar.gz"
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ vars.AWS_DEPLOY_ROLE_ARN }}
          aws-region: ${{ vars.AWS_REGION }}
          role-session-name: lab-deploy-${{ github.run_id }}
      - name: Upload and invoke one managed node
        shell: bash
        run: |
          set -euo pipefail
          aws sts get-caller-identity
          aws s3 cp "release/$RELEASE_SHA.tar.gz" "s3://$LAB_BUCKET/releases/$RELEASE_SHA.tar.gz" --sse AES256 --only-show-errors
          aws s3 cp "release/$RELEASE_SHA.tar.gz.sha256" "s3://$LAB_BUCKET/releases/$RELEASE_SHA.tar.gz.sha256" --sse AES256 --only-show-errors
          command_id=$(aws ssm send-command --document-name AwsDailyLab-Release \
            --document-version '1' --instance-ids "$INSTANCE_ID" \
            --parameters "ReleaseSha=$RELEASE_SHA" \
            --query Command.CommandId --output text)
          echo "CommandId=$command_id SHA=$RELEASE_SHA"
          for attempt in {1..180}; do
            status=$(aws ssm get-command-invocation --command-id "$command_id" \
              --instance-id "$INSTANCE_ID" --query Status --output text 2>/dev/null || true)
            case "$status" in
              Success) exit 0 ;;
              Failed|Cancelled|TimedOut|Cancelling)
                echo "Deploy failed: $status" >&2; exit 1 ;;
            esac
            sleep 5
          done
          echo 'Hết thời gian chờ; kiểm tra CommandId trước khi gửi lại' >&2
          exit 1
```

Major tags giúp đọc; trước khi dùng thật, chọn/pin SHA action đã review. Demo hiện có integration test khi DATABASE_URL được đặt; nếu đã thêm blackbox test bài 15-3, bảo đảm nó được `npm test` tìm thấy hoặc gọi explicit sau đó mà không chạy trùng server. `GetCommandInvocation` có eventual consistency; vòng chờ cho phép chưa thấy invocation trong lúc đầu, không gửi lại command. Nếu checksum hoặc upload lỗi, job dừng trước SendCommand.

## Kiểm tra kết quả

Đọc CommandId và trạng thái Success. Bằng phiên quản trị EC2, đối chiếu `/opt/aws-daily-lab/current/RELEASE_SHA` với SHA run và `pm2 describe aws-daily-lab` dưới user app. Helper đã kiểm `/ready` local; tiếp tục gọi base URL thực qua Nginx/ALB: `/health` trả `{ "status": "ok" }`, `/ready` 200, POST `/shorten` với URL mẫu trả 201 rồi GET `/r/:code` manual redirect trả 302 đúng Location. ALB health dùng liveness không chứng minh DB ready. Chỉ ghi hoàn tất sau cả hai lớp kiểm tra.

## Lỗi thường gặp

OIDC deny xem subject/audience, không thêm access key. Instance offline xem network/agent. SSM Success nhưng tuyến public 502 cần xem Nginx upstream/SG/target group. Workflow hết thời gian chờ không có nghĩa command đã dừng: đọc trạng thái hiện tại và release đang chạy trước mọi retry. Không in `.env` hoặc đưa secret vào `--parameters`.

## Dọn dẹp

Giữ ít nhất release hiện tại và một release tốt trước đó, cùng archive/checksum S3 để rollback. Chỉ xóa theo SHA đã xác minh, không wildcard. GitHub runner/DB tạm kết thúc theo job; EC2/RDS/NAT/endpoints/S3 vẫn có thể tính phí. Không hủy deploy đang chạy để tiết kiệm vài giây vì có thể để trạng thái giữa chừng; kiểm tra command rồi xử lý.
