# Tổng hợp một lô dữ liệu bằng Lambda

## Mục tiêu

Deploy handler Python tự viết, kiểm thử input hợp lệ/sai và xác nhận log có request ID. Tác vụ chỉ tổng hợp dữ liệu mẫu, không truy cập app DB và không tạo API công khai.

## Hiểu nhanh

Handler nhận event và context, trả dữ liệu JSON được. Validation giúp lỗi đầu vào hiện rõ thay vì tổng sai âm thầm. Không dùng biến global để cộng dồn: Lambda có thể tái sử dụng môi trường hoặc tạo mới, nên RAM không phải nơi giữ kết quả nghiệp vụ. Function của lab không ghi DB nên chạy lại không cộng trùng dữ liệu bền vững; nó vẫn có thể ghi thêm log.

## Thực hành

1. Cần role Lambda và log group bài 18-2. Lambda Console → Create function, tên `aws-daily-lab-summary`, runtime Python 3.13, kiến trúc phù hợp mặc định, Use an existing role → `aws-daily-lab-lambda-role`. Không bật Function URL, không thêm VPC hay trigger. Trong Configuration → General configuration đặt memory128 MB, timeout5 giây. Vẫn có chi phí invocation/duration và CloudWatch theo usage.
2. Trong file `lambda_function.py` thay code bằng đoạn sau. Handler là `lambda_function.lambda_handler`. Chọn Deploy; Save test event không thay thế Deploy code.

```python
import json

def lambda_handler(event, context):
    if not isinstance(event, dict):
        raise ValueError('event must be an object')
    window = event.get('window')
    rows = event.get('records')
    if not isinstance(window, str) or not 1 <= len(window) <= 80:
        raise ValueError('window must be a short label')
    if not isinstance(rows, list) or len(rows) > 100:
        raise ValueError('records must be a list of at most 100 rows')
    codes = set()
    total = 0
    for row in rows:
        if not isinstance(row, dict):
            raise ValueError('each row must be an object')
        code, count = row.get('code'), row.get('count')
        if not isinstance(code, str) or not 1 <= len(code) <= 64:
            raise ValueError('code must be a short string')
        if type(count) is not int or not 0 <= count <= 1000000:
            raise ValueError('count must be an integer in range')
        codes.add(code)
        total += count
    result = {'window': window, 'rows': len(rows),
              'uniqueCodes': len(codes), 'total': total}
    print(json.dumps({'kind': 'summary',
                      'requestId': context.aws_request_id, **result}))
    return result
```

3. Tạo test event `happy` bằng payload 18-1. Chạy Test hai lần: cả hai phải trả `total=10`, `uniqueCodes=2`, `rows=3`; request ID khác nhau. Tạo test thứ hai với `count:-1`, mong đợi `ValueError`; không coi chữ đỏ ở test lỗi cố tình là deploy hỏng.
4. Mở Monitor → View CloudWatch logs, vào đúng group bài trước. Tìm `kind=summary` cho test hợp lệ và log lỗi cho test sai. Code chỉ log nhãn lô và số tổng, không toàn bộ URLs, password hoặc event tùy ý. Tránh truyền thông tin cá nhân trong `window` hay `code`.
5. Thử `records:[]`: kết quả tổng0, số mã0 là hợp lệ. Thử `count:true`: bị từ chối vì bool không được coi là count; `type(count) is int` cố ý phân biệt trường hợp này.

## Kiểm tra kết quả

Lưu bảng input/output ba trường hợp happy, negative, empty; cùng tên function, runtime, memory, timeout và timestamp. Trong CloudWatch phải thấy request ID gắn với kết quả happy. Không có log ngay có thể cần chờ việc chuyển log; nếu vẫn thiếu, kiểm tra policy/resource của đúng execution role và log group name, không deploy lại code giống hệt nhiều lần.

## Lỗi thường gặp

`Runtime.HandlerNotFound` thường do sai tên file/hàm. `AccessDenied` ghi log là IAM, không phải lỗi phép cộng. Bỏ validation rồi dùng `int(count)` có thể biến input không đúng hợp đồng thành số, làm bài test sai vẫn “thành công”. Không hard-code credentials; code hiện không cần SDK hay quyền cloud API nào ngoài log của runtime.

## Dọn dẹp

Giữ function và role cho schedule. Test events chỉ chứa dữ liệu mẫu có thể giữ local. Nếu kết thúc ngày tại đây, không có lịch tự gọi nhưng function/log group vẫn còn; xóa function và log group theo tên nếu không cần. Không xóa role trước khi xác nhận hết tài nguyên tham chiếu.
