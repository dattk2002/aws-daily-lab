# Launch template và bootstrap có thể lặp lại

## Mục tiêu

Chuẩn bị launch template có phiên bản xác định, không chứa secret, và kiểm tra được máy mới tự khởi động app. Đây là lab nâng cao: cần EC2 Amazon Linux 2023 đã deploy thành công ở ngày 7–9, RDS private, ALB và quyền IAM tạo instance profile, launch template cùng `iam:PassRole` cho đúng role lab.

## Hiểu nhanh

Launch template mô tả AMI, loại máy, EBS, SG, instance profile và user data. Nó không chụp trạng thái máy đang chạy. AMI giữ code/dependencies; secret được lấy ở lúc boot. Dùng một số phiên bản cụ thể giúp biết ASG đang tạo bản nào; thay template không tự cập nhật các EC2 cũ.

Để không bắt buộc NAT Gateway, lab dùng app EC2 ở hai public subnet có route `0.0.0.0/0` tới Internet Gateway và public IPv4; chỉ cho inbound 80 từ SG của ALB. IPv4 công cộng vẫn có phí và không đồng nghĩa mở inbound. RDS ở private subnets, SG DB chỉ nhận TCP 5432 từ SG app. App egress cần 443 tới SSM API và 5432 tới SG DB; DNS VPC phải hoạt động. Không đặt EC2 vào private subnet rồi giả định nó tự gọi được API công cộng.

## Thực hành

1. Chuẩn bị một máy làm ảnh sạch: Node.js >=22.9, AWS CLI v2, Python 3, Nginx, PM2 và code bản đã test ở `/opt/aws-daily-lab/labs/url-shortener`, `npm ci --omit=dev` đã chạy. App chạy bằng user `labapp` đã tạo ở ngày 7, chỉ sở hữu thư mục app. Chép CA RDS công khai vào `/opt/aws-daily-lab/rds-ca.pem`; cấu hình Nginx từ `labs/nginx/url-shortener.conf`, bật Nginx khi boot. Chuẩn hóa `/home/labapp/.local/bin/pm2` và `/usr/bin/npm` theo kết quả `command -v`; sửa đường dẫn ví dụ nếu ảnh của bạn khác.
2. Trong Parameter Store tạo SecureString Standard `/aws-daily-lab/runtime` bằng Console, chứa JSON chỉ gồm `DATABASE_URL`, `PUBLIC_BASE_URL`, `PGSSLROOTCERT`. Dùng URI DB với tên DNS RDS và CA trên, không tắt xác minh TLS. Không nhập secret trên dòng lệnh, Git hay user data. Role EC2 trust `ec2.amazonaws.com`, quyền `ssm:GetParameter` chỉ ARN của parameter này. Nếu dùng customer managed KMS key, thêm `kms:Decrypt` đúng key và cho role trong key policy; giới hạn `kms:ViaService` tới SSM cùng Region. Tạo instance profile chứa role. Nếu dùng Session Manager, cần thêm quyền agent và kết nối API như ngày 5.
3. Trên máy làm ảnh riêng đã sao chép code sạch, chạy `sudo systemctl disable --now pm2-labapp` để tắt startup hook ngày 7; kiểm tra không còn daemon/process app đang chạy. Trước khi chụp ảnh, xóa đúng `/etc/aws-daily-lab/app.env`, mọi `.env` có secret trong app, PM2 saved dump/backups ở `/home/labapp/.pm2`, credentials trong `.aws` nếu có và log nhạy cảm; bảo đảm không còn secret trong snapshot. Không dùng máy đang phục vụ làm ảnh nếu chưa kiểm tra các vị trí này. Tạo AMI private, ghi AMI ID và snapshot ID. EBS snapshot/AMI storage phát sinh phí.
4. Tạo launch template `aws-daily-lab-lt`: chọn AMI đó, cùng kiến trúc với instance type, EBS mã hóa và `DeleteOnTermination=true`, SG app, profile vừa tạo, IMDSv2 required, bật public IPv4 trong cấu hình network interface nhưng không cố định subnet. Không gán IP/ENI của máy mẫu. Dán user data sau, thay Region và đường dẫn binary đã kiểm tra. Script per-boot nằm trên đĩa nên reboot cũng lấy lại cấu hình. Lệnh dưới là nội dung học tập để người học chủ động sử dụng, chưa được chạy trên AWS.

```bash
#!/bin/bash
set -eu
install -d -m 700 /var/lib/cloud/scripts/per-boot
cat > /var/lib/cloud/scripts/per-boot/aws-daily-lab <<'BOOT'
#!/usr/bin/python3
import json, os, subprocess
raw = subprocess.check_output([
    'aws', 'ssm', 'get-parameter', '--region', 'ap-southeast-1',
    '--name', '/aws-daily-lab/runtime', '--with-decryption',
    '--query', 'Parameter.Value', '--output', 'text'
], text=True)
settings = json.loads(raw)
env = os.environ.copy()
for key in ('DATABASE_URL', 'PUBLIC_BASE_URL', 'PGSSLROOTCERT'):
    env[key] = settings[key]
env.update(HOST='127.0.0.1', PORT='3000')
subprocess.run([
    'runuser', '-u', 'labapp', '--', '/home/labapp/.local/bin/pm2',
    'start', '/usr/bin/npm', '--name', 'aws-daily-lab', '--', 'start'
], cwd='/opt/aws-daily-lab/labs/url-shortener', env=env, check=True)
BOOT
chmod 700 /var/lib/cloud/scripts/per-boot/aws-daily-lab
/var/lib/cloud/scripts/per-boot/aws-daily-lab
```

Không thêm `set -x`, không in `raw` hoặc `env`. Không bật lại service `pm2-labapp` cũ có saved dump; chọn duy nhất bootstrap này để tránh chạy hai process. Không chạy `db:init` trên từng lần boot; schema phải được khởi tạo trước bằng bước ngày 6–7. Script thất bại dừng thay vì chạy app thiếu cấu hình.

## Kiểm tra kết quả

Launch một EC2 thử từ đúng version template và chọn public subnet lab; đây là thao tác có phí. Tại máy, kiểm tra `cloud-init status --wait`, `sudo -u labapp /home/labapp/.local/bin/pm2 status`, `curl -fsS http://127.0.0.1:3000/ready` và `curl -fsS http://127.0.0.1/health`. Mong đợi ready 200, Nginx health 200. Reboot một lần rồi kiểm tra lại. Không đưa `pm2 env` hay toàn bộ log bootstrap lên báo cáo vì có thể lộ cấu hình.

## Lỗi thường gặp

AMI sai kiến trúc không boot đúng. `AccessDenied` cần kiểm tra profile thực gắn với máy, parameter ARN/Region và KMS, không cấp `AdministratorAccess`. Timeout SSM API thường do thiếu public IP/route/egress443. PM2 gọi npm không thấy Node nếu Node chỉ cài trong nvm của `ec2-user`; ảnh cần binary dùng được với user `labapp`.

## Dọn dẹp

Sau khi máy thử reboot và ready tốt, terminate đúng EC2 thử, kiểm tra EBS tự xóa. Giữ AMI, snapshot, parameter, role và template để bài 17-3; chúng và tài nguyên nền vẫn có thể tính phí. Nếu dừng lộ trình, xóa template sau khi chắc không ASG dùng, deregister đúng AMI rồi xóa đúng snapshot không còn cần. Không xóa parameter/role dùng chung với lab khác.
