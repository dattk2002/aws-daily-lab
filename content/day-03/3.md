# Tạo schema và xác minh dữ liệu

## Mục tiêu

Tạo bảng `links` bằng script của demo và tự đọc cấu trúc trong PostgreSQL. Bài cần service `db` đang sẵn sàng, dependencies đã cài và các biến môi trường được export ở 03-2.

## Hiểu nhanh

Schema mô tả hình dạng dữ liệu và những điều DB phải bảo vệ. Với demo, mỗi code ứng với một URL, vì vậy `code` là khóa chính. `url` không được null. `created_at` mặc định lấy thời điểm hiện tại nếu thao tác ghi không cung cấp giá trị khác.

```sql
CREATE TABLE IF NOT EXISTS links (
  code TEXT PRIMARY KEY,
  url TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

Đây là cấu trúc riêng của bài lab, không phải mã sao chép từ dự án tham khảo. `IF NOT EXISTS` giúp lần chạy khởi tạo sau không lỗi chỉ vì bảng đã tồn tại. Tuy nhiên nó không tự sửa một bảng cũ sai cột; về sau thay đổi schema cần một quy trình migration có kiểm soát. Idempotent không có nghĩa mọi trạng thái DB đều được đưa về đúng cấu trúc.

Kiểu `TEXT` không tự xác minh URL dùng HTTP/HTTPS, cũng không ngăn nội dung nguy hiểm. Mã ứng dụng chịu trách nhiệm kiểm tra đầu vào phù hợp. Các ràng buộc DB giữ tính nhất quán khi có nhiều request cùng lúc, bổ sung cho kiểm tra ở server.

## Thực hành

Ở terminal đã nạp `.env`, đứng trong thư mục demo:

```bash
npm run db:init
npm run db:init
docker compose exec db psql -U lab -d lab -c '\d links'
```

Chạy khởi tạo hai lần để kiểm tra tính an toàn khi lặp của script schema. Với PostgreSQL vừa khởi tạo, lần sau có thể có thông báo bảng đã tồn tại; không được có lỗi làm script kết thúc thất bại.

Tiếp theo đọc dữ liệu mà không chèn hàng thử thủ công; API bài sau sẽ làm việc đó:

```bash
docker compose exec db psql -U lab -d lab -c 'SELECT code, url, created_at FROM links ORDER BY created_at DESC LIMIT 5;'
```

DB mới có thể trả `(0 rows)`, đó là kết quả hợp lệ. Nếu đã học lại, các hàng từ buổi trước có thể còn. Ghi số hàng quan sát được và không giả định mỗi máy bắt đầu từ DB rỗng.

Tự giải thích ba tình huống trên giấy: INSERT một code trùng; INSERT url là null; INSERT không truyền created_at. Lần lượt mong đợi lỗi khóa duy nhất, lỗi not-null và nhận timestamp mặc định.

## Kiểm tra kết quả

Kết quả `\d links` phải có ba cột, khóa chính của `code`, `url` not null và `created_at` not null với default. Hai lần `db:init` cùng thành công không đủ chứng minh cột đúng; vì vậy phải xem cả mô tả bảng.

Nếu script báo kết nối thành công nhưng `\d links` không thấy bảng, so sánh DB và schema thực tế. Node có thể đang trỏ vào một PostgreSQL khác trên host, trong khi lệnh psql ở container đọc DB của Compose. Không sửa bằng cách tạo bảng trên mọi database ngẫu nhiên.

## Lỗi thường gặp

Chưa nạp `DATABASE_URL`; DB chưa sẵn sàng; user/database khác `lab`; chạy tại root repository thay vì demo. Xóa volume để “sửa schema nhanh” làm mất toàn bộ dữ liệu local và che nguyên nhân; hãy đọc lỗi và mô tả bảng trước.

## Dọn dẹp

Giữ bảng và volume cho bài tạo link. Không cần DROP TABLE hoặc xóa hàng vì bài chỉ tạo cấu trúc và đọc dữ liệu. Muốn học lại từ đầu sau khi hoàn thành cả ngày thì dùng bước xóa volume có chủ đích ở 03-5; không áp dụng cách đó cho RDS thật.
