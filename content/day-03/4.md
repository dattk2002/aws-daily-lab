# API tạo link đầu tiên

## Mục tiêu

Chạy tiến trình Node.js và gọi `POST /shorten` bằng một URL công khai vô hại. Chứng minh response 201 tương ứng với một hàng đã lưu, thay vì chỉ nhìn server log “started”.

## Hiểu nhanh

Demo dùng HTTP server gốc của Node.js và PostgreSQL thông qua `pg`. Liveness `/health` không cần DB; readiness `/ready` thử kết nối DB. Route tạo link mới cần DB hoạt động và có schema. Khi thành công, JSON trả về có `code` và `shortUrl`; độ dài/code cụ thể có thể khác giữa các lần gọi, không hard-code code của người khác.

`Content-Type: application/json` cho server biết kiểu body bạn gửi. Phương thức POST thể hiện thao tác tạo; gõ URL `/shorten` vào thanh địa chỉ trình duyệt sẽ gửi GET và không thực hiện cùng thao tác. Một thông báo trong terminal không thay thế việc kiểm tra status, header và body thực tế.

## Thực hành

Dùng hai terminal. Terminal A ở `labs/url-shortener`, đã nạp `.env` ở 03-2 và đã chạy schema:

```bash
set -a
source .env
set +a
npm start
```

Giữ terminal A mở. Ở terminal B, kiểm tra đường HTTP trước khi tạo dữ liệu:

```bash
curl --silent --show-error -i http://127.0.0.1:3000/health
curl --silent --show-error -i http://127.0.0.1:3000/ready
```

Cả hai nên trả 200 khi app và DB sẵn sàng. Sau đó gọi API tạo link:

```bash
curl --silent --show-error -i \
  -X POST http://127.0.0.1:3000/shorten \
  -H 'Content-Type: application/json' \
  --data '{"url":"https://example.com"}'
```

Kỳ vọng 201 và body dạng `{"code":"...","shortUrl":"http://127.0.0.1:3000/r/..."}`. Dấu `...` chỉ minh họa, không phải code để gửi request. Sao chép code thật vào ghi chú để dùng bài sau.

Trong terminal B, chuyển vào thư mục demo và xác minh hàng mới:

```bash
cd labs/url-shortener
docker compose exec db psql -U lab -d lab -c 'SELECT code, url, created_at FROM links ORDER BY created_at DESC LIMIT 5;'
```

Nếu terminal B đã ở thư mục demo, bỏ qua lệnh cd. Không dựng SQL bằng cách ghép một URL người lạ cung cấp; truy vấn cố định ở đây chỉ đọc các hàng gần nhất.

## Kiểm tra kết quả

Status phải là 201, `code` không rỗng, `shortUrl` bắt đầu bằng base local và có path `/r/<code>`. Một hàng DB phải có đúng code và URL `https://example.com` tương ứng. Nếu response cho 201 nhưng bạn không thấy hàng, kiểm tra app đang dùng DB nào trước khi kết luận API sai.

Thử body thiếu trường URL bằng `--data '{}'` và ghi status lỗi 4xx thực tế. Không yêu cầu chuỗi thông báo lỗi phải giống một phiên bản tài liệu; điều cần chứng minh là dữ liệu không hợp lệ không nhận 201. Không sử dụng link riêng tư hoặc token trong query string để thử API.

## Lỗi thường gặp

`Connection refused` thường do app chưa chạy hoặc sai cổng; `/ready` 503 gợi ý kiểm tra kết nối DB/schema tùy implementation. `EADDRINUSE` nghĩa cổng 3000 đã bị sử dụng, cần tìm tiến trình đúng thay vì đổi port mà quên PUBLIC_BASE_URL. Body JSON dùng dấu nháy không hợp lệ khiến request thất bại trước bước lưu.

## Dọn dẹp

Giữ app, DB và code vừa tạo để kiểm tra redirect ở bài kế tiếp. Nếu nghỉ, dừng Node bằng Ctrl+C ở terminal A và `docker compose stop db`; dữ liệu vẫn ở volume. Lệnh bài này chỉ tạo dữ liệu local, không chạm AWS hoặc gửi request đến website đích.
