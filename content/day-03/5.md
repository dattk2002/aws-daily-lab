# Redirect, readiness và test

## Mục tiêu

Kiểm tra code đã tạo, chứng minh dữ liệu qua restart Node.js và phân biệt process sống với DB sẵn sàng. Bài cần app, DB và ít nhất một link của 03-4. Chỉ gây gián đoạn database local thuộc Compose của demo.

## Hiểu nhanh

Response redirect chứa `Location`; trình duyệt thường theo nó tự động. `curl -i` mặc định chưa theo redirect, giúp thấy 302 ban đầu. Nếu dùng `-L`, output cuối có thể là 200 của website đích; vì vậy không dùng nó làm bằng chứng duy nhất cho app.

Một test tự động kiểm tra logic theo những điều kiện đã lập trình. Nó bổ sung cho smoke test app–DB thật chứ không thay thế mọi bằng chứng vận hành. Cần đọc tên test và summary trước khi nói test bao phủ DB hoặc mạng AWS; tests chạy trên máy local không chứng minh Security Group cloud đúng.

## Thực hành

Ở terminal B, nhập code thật đã nhận; prompt tránh hard-code một giá trị giả trong lệnh:

```bash
read -r -p 'Nhap code vua tao: ' CODE
curl --silent --show-error -i "http://127.0.0.1:3000/r/$CODE"
curl --silent --show-error -i http://127.0.0.1:3000/r/code-chua-tao-trong-lab
```

Kỳ vọng request đầu là 302 với `Location: https://example.com`; request code chưa từng tạo là 404. Trên terminal A, Ctrl+C rồi `npm start` lại với cùng môi trường. Chạy lại request đầu trên terminal B với nguyên CODE cũ; kết quả vẫn phải trỏ đúng URL.

Tiếp theo, terminal B phải đứng tại `labs/url-shortener`:

```bash
docker compose stop db
curl --silent --show-error -i http://127.0.0.1:3000/health
curl --silent --show-error -i http://127.0.0.1:3000/ready
docker compose start db
docker compose exec db pg_isready -U lab -d lab
```

Sau khi DB nhận kết nối trở lại, kiểm tra `/ready` và code cũ lần nữa. Nếu DB chưa kịp sẵn sàng, chờ trạng thái nhận kết nối rồi thử lại; không spam tạo process mới. Trong trạng thái DB dừng, mong đợi `/health` 200 và `/ready` 503 khi tiến trình HTTP vẫn hoạt động.

Cuối cùng, với DB local đang chạy và cấu hình dummy đã nạp, chạy bộ test từ thư mục demo:

```bash
set -a
source .env
set +a
npm test
```

Đọc summary và tên test. Chỉ ghi “pass” khi exit code là 0 và không có ca thất bại; nếu tests dùng fake/in-memory repository, ghi rõ giới hạn đó bên cạnh smoke test PostgreSQL bạn vừa thực hiện.

## Kiểm tra kết quả

Hoàn thiện checklist ngày 1 bằng status, Location, trước/sau restart và readiness khi DB dừng/khôi phục. Khi DB phục hồi, code cũ vẫn dùng được vì `stop/start` không xóa volume. Ghi việc test chưa chạy hoặc fail đúng như thực tế, không đánh dấu hoàn thành bằng cách bỏ qua lỗi.

Nếu app không phục hồi sau DB start, giữ log lỗi đã che bí mật và kiểm tra pool kết nối, cấu hình DB, trạng thái container. Đây là thông tin hữu ích trước khi học triển khai, không phải lý do tự động cài lại toàn bộ máy.

## Lỗi thường gặp

Đọc 200 sau redirect là kết quả của Node; restart DB bằng `down -v` rồi ngạc nhiên vì mất code; chạy npm test từ root UI; stop nhầm database dùng cho dự án khác. Luôn đứng đúng thư mục và xác nhận Compose project trước thao tác gián đoạn.

## Dọn dẹp

Khi hoàn thành, Ctrl+C dừng app và `docker compose stop db` giữ dữ liệu cho lần sau. Nếu chủ đích xóa toàn bộ dữ liệu local của demo, kiểm tra đúng thư mục rồi chạy `docker compose down -v`; lệnh xóa container và volume của Compose project này, code đã tạo sẽ mất. Không dùng lệnh Docker prune toàn máy. Xóa file ghi chú chứa URL riêng nếu có; các bài cloud sau dùng cấu hình DB riêng.
