# Chuẩn bị Node.js và PostgreSQL local

## Mục tiêu

Chạy PostgreSQL 17 local và kiểm tra được trạng thái sẵn sàng trước khi ứng dụng kết nối. Ngày này dùng demo tự viết tại `labs/url-shortener`, không tải mã từ một khóa học khác và không cần credentials AWS.

## Hiểu nhanh

Ứng dụng cần Node.js từ phiên bản 22 trở lên và package `pg`; database local chạy bằng Docker Compose. Root repository còn có package dành cho giao diện đọc bài. Vì vậy các lệnh npm của demo phải chạy trong `labs/url-shortener`, không chạy nhầm tại root rồi kết luận thiếu script.

Container đang Running chỉ cho biết tiến trình container chưa kết thúc; DB vẫn có thể đang khởi tạo. `pg_isready` cho một tín hiệu rõ hơn về việc PostgreSQL nhận kết nối. Sau đó ta vẫn phải xác minh schema và truy vấn: một server nhận TCP không bảo đảm đã có bảng `links`.

User, password và database tên `lab` trong Compose chỉ là dữ liệu giả định cho máy local. Cổng DB phải bind về loopback của máy, không đem cấu hình đó lên EC2 hay mở PostgreSQL ra Internet. Lab local sử dụng CPU, RAM, ổ đĩa và có thể tải container image; không tạo dịch vụ AWS và không phát sinh phí cloud từ các lệnh này.

## Thực hành

Chuẩn bị Node.js >=22, npm, Docker với Compose v2, Bash và curl trên Linux/macOS hoặc WSL2. Mở terminal tại root repository rồi chạy:

```bash
node --version
npm --version
docker --version
docker compose version
cd labs/url-shortener
npm ci
docker compose up -d db
docker compose ps
```

`npm ci` dùng lockfile của demo, cài dependency đúng phiên bản và thay nội dung `node_modules` local. Lệnh không chạy từ root UI. Nếu Docker daemon chưa hoạt động, khởi động Docker theo nền tảng rồi chạy lại lệnh Compose; không đổi quyền toàn bộ socket thành public.

Kiểm tra DB sau khi container khởi tạo:

```bash
docker compose exec db pg_isready -U lab -d lab
```

Kỳ vọng có thông điệp `accepting connections`. Nếu chưa, xem log có giới hạn rồi kiểm tra lại sau khi tiến trình khởi tạo hoàn tất:

```bash
docker compose logs --tail=40 db
```

Đừng paste log chứa cấu hình thật từ hệ thống khác; ở đây chỉ dùng database local của Compose. Chưa cần chạy npm start vì bài tiếp theo mới cấu hình môi trường và bài 03-3 mới tạo bảng.

## Kiểm tra kết quả

Ghi lại version Node.js, version Compose và kết quả `pg_isready`. Node phải đáp ứng yêu cầu >=22; PostgreSQL image của Compose là `postgres:17-alpine`. Không dùng `docker ps` trống ở terminal khác để kết luận khi bạn đang kết nối một Docker context khác.

Đầu ra đạt là service `db` đang chạy và nhận kết nối. Bài chưa chứng minh app HTTP hoạt động, chưa có dữ liệu link và không được đánh dấu các ca HTTP ở ngày 1 là hoàn thành.

## Lỗi thường gặp

Cổng 5432 đã được PostgreSQL khác sử dụng làm Compose không start được; phải nhận diện tiến trình đang dùng cổng và giải quyết có chủ đích, không kill bừa. `npm ci` báo không thấy lockfile thường do bạn đứng sai thư mục hoặc checkout thiếu file. Quyền Docker thiếu cần xử lý theo hướng dẫn nền tảng thay vì dùng sudo cho mọi lệnh npm.

## Dọn dẹp

Giữ service `db` để học bài tiếp theo. Nếu cần nghỉ, chạy `docker compose stop db` trong thư mục demo; dữ liệu volume vẫn còn. Muốn khởi động lại dùng `docker compose start db`. Chưa xóa volume vì sẽ mất schema và dữ liệu của các bài kế tiếp.
