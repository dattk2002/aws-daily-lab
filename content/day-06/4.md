# Kết nối PostgreSQL bằng TLS xác minh đầy đủ

## Mục tiêu

Dùng `psql` trên EC2 kết nối RDS với `sslmode=verify-full`, CA bundle đúng và password nhập tương tác. Phân biệt “có mã hóa” với “đã xác minh server là database mong đợi”.

## Hiểu nhanh

TLS cần kiểm tra chuỗi chứng chỉ và hostname để hạn chế kết nối tới server giả. `prefer` có thể cho phép fallback; `require` không diễn đạt đầy đủ yêu cầu xác minh danh tính. Ta dùng endpoint DNS RDS gốc với `verify-full`, không thay bằng private IP hoặc alias chưa có trong chứng chỉ. Encryption-at-rest không bảo vệ luồng kết nối này.

Điều kiện: TCP ngày 06-3 đã hoạt động, DB Available, master credentials ở password manager, đồng hồ máy hợp lý. CA bundle là dữ liệu công khai; password là secret. Với RDS PostgreSQL, giá trị mặc định `rds.force_ssl` tùy phiên bản; đọc parameter group thực tế thay vì đoán. Lab phải luôn xác minh từ client; nếu muốn bắt buộc mọi client TLS, dùng parameter group phù hợp engine đặt `rds.force_ssl=1`, đọc apply method và reboot khi được yêu cầu.

## Thực hành

Trong EC2, cài client PostgreSQL tương thích. Ví dụ AL2023 có package client `postgresql17`; xác minh bằng `dnf info` trước khi cài nếu release khác:

```bash
sudo dnf install -y postgresql17
sudo install -d -o root -g root -m 755 /etc/aws-daily-lab
sudo curl --fail --show-error --location \
  https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem \
  -o /etc/aws-daily-lab/global-bundle.pem
sudo chmod 644 /etc/aws-daily-lab/global-bundle.pem
psql "host=<RDS_ENDPOINT_DNS> port=5432 dbname=lab user=labadmin sslmode=verify-full sslrootcert=/etc/aws-daily-lab/global-bundle.pem" -W
```

Thay endpoint, nhập password khi được hỏi; đừng thêm `password=` vào command. Trong psql chạy:

```sql
\conninfo
SELECT ssl, version, cipher FROM pg_stat_ssl WHERE pid = pg_backend_pid();
SELECT current_database(), current_user;
```

Giữ file bundle cập nhật từ nguồn AWS khi chuẩn bị rotation CA. Một CA đúng không có nghĩa dùng được mãi mà không theo dõi thời hạn và thông báo rotation.

## Kiểm tra kết quả

`\conninfo` báo SSL, truy vấn `pg_stat_ssl` có `ssl=t`, database là `lab`, user là `labadmin`. Việc xác minh danh tính dựa thêm vào cấu hình `verify-full` và hostname chính xác trong command; chỉ `ssl=t` chưa chứng minh hostname đã được kiểm tra. Để thử lỗi an toàn, chỉ định đường CA không tồn tại cho một phiên mới: client phải báo lỗi, không hạ xuống kết nối không kiểm chứng.

## Lỗi thường gặp

CA file missing: sửa đường dẫn/quyền đọc file công khai. Certificate verify failed: kiểm tra bundle, đồng hồ, endpoint và rotation. Password authentication failed: sửa credentials, không đổi SSL để thử. Không dùng `NODE_TLS_REJECT_UNAUTHORIZED=0` hoặc `rejectUnauthorized:false`; chúng che mất yêu cầu bảo mật vừa đặt ra.

## Dọn dẹp

Thoát psql bằng `\q`; giữ CA công khai cho ngày 07, không ghi password vào shell history. DB/EC2 đang chạy vẫn có chi phí. Nếu dừng lab, thực hiện teardown DB rồi EC2 như bài trước và kiểm tra snapshot/đĩa còn lại.
