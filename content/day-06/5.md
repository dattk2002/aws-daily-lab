# Tạo user ứng dụng và schema links

## Mục tiêu

Tạo user PostgreSQL `labapp` cho demo, cấp quyền trong database `lab` và khởi tạo đúng bảng `links`. Xác minh quyền sở hữu và truy vấn thật trước khi triển khai Node, không dùng master user trong ứng dụng.

## Hiểu nhanh

User hệ điều hành và role PostgreSQL là hai danh tính khác nhau dù cùng tên `labapp`. Master `labadmin` chỉ làm bước chuẩn bị. Lab gộp quyền migration và runtime vào `labapp` cho dễ học; một hệ thống lớn nên tách quyền DDL/migration khỏi quyền đọc ghi runtime. Không cấp superuser, quyền quản trị RDS hoặc quyền tới database khác cho demo.

Demo gốc của repository yêu cầu bảng `links` gồm `code TEXT PRIMARY KEY`, `url TEXT NOT NULL`, `created_at TIMESTAMPTZ NOT NULL DEFAULT now()`. Tạo schema idempotent giúp chạy lại setup không xóa dữ liệu. Nó không tự thay đổi cấu trúc một bảng cũ đã sai; cần kiểm tra schema thay vì thấy command thành công rồi bỏ qua.

## Thực hành

Mở psql bằng `labadmin`, TLS như bài 06-4. Tạo role một lần, rồi đặt password bằng prompt riêng để không viết password vào command hoặc file SQL:

```sql
CREATE ROLE labapp LOGIN;
\password labapp
GRANT CONNECT ON DATABASE lab TO labapp;
GRANT USAGE, CREATE ON SCHEMA public TO labapp;
```

Nếu role đã có, kiểm tra nó và chỉ đổi password khi có chủ đích; không chạy lại `CREATE ROLE` mù quáng. Thoát và kết nối lại bằng `user=labapp`, `dbname=lab`, cùng endpoint/CA/`sslmode=verify-full`, thêm `-W` để nhập password. Trong phiên app user:

```sql
CREATE TABLE IF NOT EXISTS links (
  code TEXT PRIMARY KEY,
  url TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
\d links
SELECT tablename, tableowner FROM pg_tables
WHERE schemaname = 'public' AND tablename = 'links';
BEGIN;
INSERT INTO links(code, url) VALUES ('dbcheck', 'https://example.com');
SELECT code, url FROM links WHERE code = 'dbcheck';
ROLLBACK;
```

Transaction thử rồi rollback giữ database sạch. Khi deploy từ source, `npm run db:init` trong `labs/url-shortener/` cũng khởi tạo bảng này; chạy bằng cùng role để quyền sở hữu nhất quán.

## Kiểm tra kết quả

`tableowner` là `labapp`, `\d` hiển thị primary key trên code và default timestamp. Truy vấn trong transaction trả một hàng; sau rollback `SELECT count(*) FROM links WHERE code='dbcheck';` trả 0 nếu chưa có mã đó trước lab. Ghi schema và tên role, tuyệt đối không lưu password trong ghi chú public. Endpoint health của app chưa chạy; truy vấn DB thành công mới là bằng chứng ở lớp này.

## Lỗi thường gặp

Permission denied for schema public nghĩa là thiếu quyền schema hoặc đang ở sai database. Bảng thuộc `labadmin` có thể cho đọc nhưng migration/app chưa có quyền cần thiết; với DB lab mới, tạo bảng bằng app user ngay từ đầu. Không dùng DROP TABLE để sửa khi đã có dữ liệu cần giữ. Database name không tồn tại phải xử lý ở kết nối/khởi tạo DB, không đổi sang database `postgres` rồi tạo bảng lạc chỗ.

## Dọn dẹp

Rollback bản ghi thử, thoát psql và giữ user/bảng cho ngày 07. Không drop role khi app sắp dùng nó. Khi hoàn tất toàn lab, xóa đúng DB instance và kiểm tra snapshots/backup còn lại; nếu chỉ xóa dữ liệu test hãy lọc theo mã đã biết, không dùng DELETE toàn bảng.
