# CLI và kiểm tra identity

## Mục tiêu

Chạy một lệnh chỉ đọc để xác nhận tài khoản và principal thật mà CLI dùng. Bài cần AWS CLI v2 và lối truy cập làm việc đã chuẩn bị ở 02-2; không yêu cầu access key root hoặc tự mở Organizations.

## Hiểu nhanh

AWS CLI biến lệnh thành request AWS API. Profile là tên cấu hình trên máy; gọi profile là `lab` không bảo đảm nó trỏ đúng account. Credentials có thể đến từ phiên SSO, cấu hình assume-role hoặc môi trường. Region trong profile quyết định nơi nhiều API thao tác, còn STS identity giúp bạn biết principal đang ký request.

Nếu tổ chức đã cấp IAM Identity Center, wizard SSO có thể tạo profile gắn session để CLI lấy credentials tạm. Bạn cần Start/Issuer URL, SSO Region và account/role đã được cấp. SSO Region có thể khác Region triển khai EC2. Không tự phát minh URL portal hoặc tạo tài khoản mới khi danh sách role trống.

## Thực hành

Các lệnh dưới đây chỉ đăng nhập và đọc identity; chạy từ Bash trên máy cá nhân. Cài CLI v2 bằng hướng dẫn chính thức đúng Linux/macOS/WSL2 trước khi tiếp tục. Không chạy bộ cài cho nền tảng khác.

```bash
aws --version
```

Kỳ vọng bắt đầu bằng `aws-cli/2`. Nếu bạn đã có SSO được cấp, thực hiện:

```bash
aws configure sso --profile lab
aws sso login --profile lab
aws sts get-caller-identity --profile lab --output json
```

Trong wizard, chọn account lab và role đúng; đặt default Region theo 01-4, output JSON. Với profile assume-role đã chuẩn bị sẵn, bỏ qua hai lệnh SSO và dùng tên profile đó ở lệnh identity. Không nhập credentials trực tiếp vào code bài học.

Response ví dụ về hình dạng, các giá trị không phải tài khoản để bạn sử dụng:

```json
{
  "UserId": "EXAMPLE:session",
  "Account": "123456789012",
  "Arn": "arn:aws:sts::123456789012:assumed-role/LabRole/session"
}
```

So sánh Account với hồ sơ lab và phần role trong Arn với quyền đã được cấp. Không tiếp tục các lệnh tạo cloud nếu Arn là root hoặc account khác. Kiểm tra cấu hình Region mà không in secret:

```bash
aws configure get region --profile lab
```

Nếu chưa có đường truy cập phù hợp, lưu checklist “CLI cài xong / identity chưa chạy” và hoàn thành phần local ở ngày 3 trước.

## Kiểm tra kết quả

Bạn phải có output identity thật với đúng account/role và một default Region rõ ràng, hoặc ghi chính xác phần còn thiếu. Chỉ `aws --version` thành công chưa chứng minh bạn đăng nhập AWS được. Chỉ đăng nhập trình duyệt cũng chưa chứng minh shell hiện tại dùng cùng identity.

Ghi ngày kiểm tra, tên profile và kết quả khớp; khi chia sẻ, che Account/UserId nếu không cần công khai. Trước mỗi đợt tạo hoặc xóa tài nguyên sau này, chạy lại identity: phiên và cấu hình máy có thể đã đổi.

## Lỗi thường gặp

`Unable to locate credentials` nghĩa CLI chưa tìm thấy nguồn hợp lệ; `ExpiredToken` cần làm mới đúng phiên; sai SSO Region có thể làm đăng nhập thất bại. Một biến credentials cũ trong môi trường có thể gây nhầm với profile khác; kiểm tra tên biến và nguồn cấu hình một cách riêng tư, không chạy `env` rồi dán toàn bộ output lên trang công khai.

## Dọn dẹp

Giữ profile cho các ngày sau trên máy riêng. Với SSO, `aws sso logout` đăng xuất các session SSO được cache trên máy; lưu ý ảnh hưởng các profile SSO khác. Không xóa role hoặc permission set của tổ chức. Không có tài nguyên compute được tạo và lệnh identity không triển khai hạ tầng.
