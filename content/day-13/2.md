# Object key là địa chỉ dữ liệu

## Mục tiêu

Upload một JSON không nhạy cảm, đọc lại đúng nội dung và phân biệt tên file local với key trên S3. Đầu ra là một object tại `scratch/request-example.json`, không phải bản sao database và không chứa URL khách hàng thật.

## Hiểu nhanh

S3 dùng bucket và key để xác định object. Dấu `/` giúp tổ chức prefix nhưng không tạo cây thư mục như ổ đĩa. `scratch/A.json` và `scratch/a.json` là hai key khác nhau. Khi bucket chưa bật versioning, upload lại cùng key thay thế dữ liệu hiện tại; vì vậy backup nên dùng key có timestamp thay vì `latest.dump` duy nhất. Không đưa password hoặc token vào key vì tên xuất hiện trong nhiều công cụ quan sát.

## Thực hành

Dùng lại `LAB_BUCKET` và `AWS_REGION` của bài trước trong cùng shell. Tạo file nhỏ, upload và tải về một đường dẫn khác để không tự so sánh file với chính nó:

```bash
mkdir -p /tmp/aws-daily-lab-s3
printf '%s\n' '{"lesson":"13-2","result":"sample"}' \
  > /tmp/aws-daily-lab-s3/source.json
aws s3api put-object --bucket "$LAB_BUCKET" \
  --key scratch/request-example.json \
  --body /tmp/aws-daily-lab-s3/source.json --content-type application/json
aws s3api head-object --bucket "$LAB_BUCKET" --key scratch/request-example.json
aws s3api get-object --bucket "$LAB_BUCKET" \
  --key scratch/request-example.json /tmp/aws-daily-lab-s3/download.json
cmp /tmp/aws-daily-lab-s3/source.json /tmp/aws-daily-lab-s3/download.json
```

`ContentType` giúp client hiểu representation nhưng không xác thực JSON, không bảo vệ file và không chạy mã phía S3. Sửa giá trị `result` trong local rồi dự đoán object có đổi ngay không: đáp án là chưa, cần một request upload mới. Viết dự đoán trước khi thử.

## Kiểm tra kết quả

```bash
aws s3api list-objects-v2 --bucket "$LAB_BUCKET" --prefix scratch/ \
  --query 'Contents[].{Key:Key,Size:Size}'
```

Danh sách chứa đúng key, kích thước khác 0; `cmp` exit code 0 chứng minh byte tải về trùng file đã gửi. `ETag` không phải bằng chứng MD5 phổ quát vì multipart upload và các chế độ mã hóa ảnh hưởng cách tính. Với bài này, so sánh bytes hoặc SHA-256 của hai file local là kiểm tra dễ hiểu hơn. Ghi thêm một câu giải thích vì sao URL object private không phải link tải public.

## Lỗi thường gặp

`NoSuchKey` thường do khác chữ hoa, thiếu prefix hoặc gửi nhầm bucket. `head-object` trả 403 có thể do thiếu quyền, không đủ để kết luận object tồn tại hay không. File tải về vào tên đang có sẽ ghi đè local; dùng thư mục riêng. Đừng nhầm policy ListBucket trên ARN bucket với GetObject trên ARN object: đó là hai phạm vi quyền khác nhau.

## Dọn dẹp

Giữ object `scratch/request-example.json` để so sánh quyền ở bài cuối ngày. File nhỏ vẫn có phí API và lưu trữ; nếu dừng, xóa đúng object bằng `aws s3api delete-object --bucket "$LAB_BUCKET" --key scratch/request-example.json`. Nếu sau này bật versioning, xóa current version chỉ tạo delete marker; cần kiểm tra phiên bản còn lại trước khi tính tài nguyên đã sạch.
