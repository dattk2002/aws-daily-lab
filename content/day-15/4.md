# Kiểm tra source và đóng gói artifact

## Mục tiêu

Phân biệt lint, typecheck, test, build và tạo archive demo có thể đối chiếu với commit. Artifact không chứa `.env`, DB dump hay credentials. Static `dist/` của website và archive ứng dụng Node là hai sản phẩm khác nhau.

## Hiểu nhanh

Lint phát hiện quy ước hoặc lỗi khả nghi; typecheck xác minh kiểu trong phần TypeScript; test đo hành vi; build tạo output deploy. Demo native JavaScript không tự có TypeScript chỉ vì website dùng TypeScript. Không viết `npm run build --if-present` rồi gọi đó là bằng chứng demo đã build: Node runtime của bài được đóng gói source. Artifact upload của GitHub giúp review, còn S3 artifact cho CD cần cơ chế tải và xác minh riêng.

## Thực hành

Đọc scripts root trước; với repository giáo trình, chạy check:content, typecheck, test và build đã khai báo; root không khai báo script lint riêng. Khi một script chưa tồn tại, bổ sung công cụ có chủ ý trong bản học hoặc ghi thiếu kiểm tra; không lặng lẽ bỏ qua. Tạo job `website` độc lập với job PostgreSQL:

```yaml
  website:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm run check:content
      - run: npm run typecheck
      - run: npm test
      - run: npm run build
```

Nếu root đã có workflow tương đương, dùng workflow đó, không tạo job duplicate. Với artifact demo, chỉ chạy đoạn sau sau khi job `demo` đã test pass; lệnh `git archive` chạy từ repository root và chỉ lấy file được tracked trong demo, loại secrets không bao giờ được tracked:

```bash
mkdir -p release
RELEASE_SHA="$(git rev-parse HEAD)"
git archive --format=tar.gz \
  --output="release/$RELEASE_SHA.tar.gz" HEAD labs/url-shortener
(cd release && sha256sum "$RELEASE_SHA.tar.gz" > "$RELEASE_SHA.tar.gz.sha256")
tar -tzf "release/$RELEASE_SHA.tar.gz"
```

Xem listing để chắc source runtime, SQL schema, package.json và package-lock.json có mặt; tests có thể đi kèm vì không bí mật, nhưng không cần node_modules. Nếu `.env`/dump đã từng bị tracked, dừng xử lý dữ liệu và xoay secrets bị lộ trước, không dựa vào `.gitignore` để che lịch sử.

Để lưu evidence trong CI, thêm step với `working-directory` root nếu job mặc định ở demo:

```yaml
      - uses: actions/upload-artifact@v4
        with:
          name: demo-source-${{ github.sha }}
          path: |
            release/*.tar.gz
            release/*.sha256
          if-no-files-found: error
          retention-days: 3
```

Step đóng gói phải đứng trước step upload trong cùng workspace. Không upload toàn repository bằng `path: .`.

## Kiểm tra kết quả

Tải artifact từ đúng run, kiểm checksum và giải nén trong thư mục tạm. Cần `npm ci --omit=dev` ở package demo để chạy runtime; archive không chứa node_modules. SHA trong tên đối chiếu commit đã test. Review thông tin cấu hình mẫu bảo đảm local dummy credentials không bị mô tả như production secrets.

## Lỗi thường gặp

Working directory `labs/url-shortener` khiến output `release/` nằm sai chỗ nếu chưa về root. Root `dist/` không có Node server. `npm ci` cần lockfile khớp package manifest; không tạo lại lockfile ngay trên máy production. Archive cùng checksum không phải chữ ký chống giả mạo, nên quyền ghi artifact và source commit vẫn cần kiểm soát.

## Dọn dẹp

Artifact có storage/retention theo plan GitHub; xóa run artifact thử khi không cần. `release/` local có thể xóa đúng thư mục sau khi lưu bằng chứng. Không tạo hoặc xóa AWS resources trong bài này. Giữ một archive sạch và checksum để học CD; không tự publish website từ job này.
