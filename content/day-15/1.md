# Workflow là bằng chứng có thể lặp lại

## Mục tiêu

Thiết kế CI cho hai phần repository: website đọc bài và API Node/PostgreSQL. Đầu ra là sơ đồ job cùng workflow tối thiểu chỉ kiểm tra, không triển khai AWS và không publish GitHub Pages.

## Hiểu nhanh

CI chạy một tập kiểm tra trên commit cụ thể. Dấu xanh chỉ có ý nghĩa khi những điều quan trọng thực sự được assert. Một job chỉ `npm install` rồi echo “success” không chứng minh redirect hay database hoạt động. Website root build ra static assets; URL shortener ở `labs/url-shortener` chạy HTTP và cần PostgreSQL. Hai package có working directory và lockfile riêng. Tách job giúp lỗi nội dung/UI không bị nhầm với lỗi database.

## Thực hành

Trong bản fork hoặc checkout dành cho bài học, mở root `package.json` và `labs/url-shortener/package.json`, ghi các scripts thực tế trước khi viết YAML. Các bài này cung cấp snippet để người học chủ động tạo file; không yêu cầu bạn bật workflow cloud ngay. Tạo `.github/workflows/app-ci.yml` riêng, bắt đầu bằng:

```yaml
name: App CI
on:
  push:
    branches: [main]
  pull_request:
permissions:
  contents: read
concurrency:
  group: app-ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  demo:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: labs/url-shortener
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
          cache-dependency-path: labs/url-shortener/package-lock.json
      - run: npm ci
      - run: npm test
```

Đây là bước đầu, chưa có integration database; bài tiếp theo bổ sung service và schema. Action major version là mốc dễ đọc trong giáo trình; với repository thật, kiểm tra release upstream và pin full commit SHA đã duyệt để tăng khả năng lặp lại. Không sao chép SHA ngẫu nhiên. Workflow này tuyệt đối không có `id-token: write`, access key hay deploy step.

Vẽ luồng commit → checkout → cài đúng lockfile → unit tests → integration với PostgreSQL → đóng gói. Viết cạnh mỗi mũi tên điều kiện để đi tiếp. Xác định job build website riêng nếu đã có root workflow; tránh tạo job trùng chỉ vì tên file khác.

## Kiểm tra kết quả

Chỉ ra đúng working directory cho từng lệnh và giải thích tại sao `npm ci` root không cài dependency của demo. Trong Actions UI, kiểm tra event, branch và SHA của run khớp commit đã chọn. Nếu chưa push hoặc chưa được phép chạy remote, kiểm tra YAML và chạy commands tương ứng local; ghi rõ chưa có bằng chứng runner thật. GitHub Actions có giới hạn sử dụng/storage theo plan, không phải tài nguyên luôn miễn phí.

## Lỗi thường gặp

Sai indentation làm `permissions` rơi vào một job khác. `pull_request_target` có quyền ngữ cảnh khác và không cần cho lab này; không chạy source PR không tin cậy với secrets. Dùng `npm install` thay `npm ci` có thể che lockfile thiếu đồng bộ. Đặt AWS credentials để test DB tạm vừa thừa vừa mở rộng rủi ro.

## Dọn dẹp

Không tạo AWS resources. Giữ workflow cho bài sau. Hủy run bị treo trong Actions UI nếu có; xóa artifact cũ khi hết retention. Không tắt mọi kiểm tra vì một lỗi setup. Các workflow Pages của website và CD ứng dụng sẽ có trigger/quyền khác, không ghép chúng vào job CI này.
