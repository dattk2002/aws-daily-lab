# PostgreSQL service trong CI

## Mục tiêu

Cấp PostgreSQL 17 tạm cho job, chờ database sẵn sàng và chạy schema/test của demo. Database này bị bỏ sau run; nó không truy cập RDS production và không cần mở Security Group.

## Hiểu nhanh

Service container cùng vòng đời với job. Khi job chạy trực tiếp trên Ubuntu runner và publish `5432:5432`, app dùng `127.0.0.1:5432`. Nếu đổi sang job có `container:`, hostname là service label như `postgres`, với networking khác. Health check `pg_isready` chỉ chứng minh server nhận kết nối; app vẫn cần database, user và schema đúng. Mật khẩu `lab` dưới đây chỉ dùng database tạm cô lập, không phải cấu hình cloud.

## Thực hành

Thay job `demo` bài trước bằng cấu trúc dưới, giữ phần `on`, permissions và concurrency. Không thêm secret RDS vào workflow:

```yaml
  demo:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:17-alpine
        env:
          POSTGRES_USER: lab
          POSTGRES_PASSWORD: lab
          POSTGRES_DB: lab
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U lab -d lab"
          --health-interval 5s
          --health-timeout 5s
          --health-retries 10
    env:
      DATABASE_URL: postgres://lab:lab@127.0.0.1:5432/lab
      HOST: 127.0.0.1
      PORT: '3100'
      PUBLIC_BASE_URL: http://127.0.0.1:3100
    defaults:
      run:
        working-directory: labs/url-shortener
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
          cache-dependency-path: labs/url-shortener/package-lock.json
      - run: npm ci
      - run: npm run db:init
      - run: npm test
```

Job này gọi native Node tests hiện có của demo. Bài tiếp thêm blackbox test kiểm tra dữ liệu đi qua HTTP; đừng suy luận `npm test` nhất thiết bao phủ PostgreSQL nếu chưa đọc test. Với local, `docker compose -f labs/url-shortener/compose.yaml up -d` tạo DB cùng thông tin lab; chạy commands tương ứng trong demo. Không dùng `.env.example` để cấu hình RDS thật.

## Kiểm tra kết quả

Mong đợi service healthy, `db:init` exit 0 và tests có số lượng assertion thực tế. SQL schema idempotent tạo bảng `links (code TEXT PRIMARY KEY, url TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now())`; chạy init hai lần không được mất link. Kiểm tra test không có nhánh skip khi thiếu DATABASE_URL làm CI xanh giả. Nếu chưa có test tích hợp, đánh dấu phạm vi hiện tại và hoàn thành bài 3 trước khi coi job kiểm tra API đầy đủ.

## Lỗi thường gặp

`ENOTFOUND postgres` trong job chạy trực tiếp trên runner thường do dùng hostname của job container. `ECONNREFUSED` có thể do thiếu mapping hoặc service chết. `password authentication failed` kiểm tra ba giá trị service env trùng URL. Không chữa timeout bằng `sleep 60` cố định: health check có retry và timeout rõ. Chứng chỉ RDS không liên quan DB local không TLS này; production vẫn phải verify TLS.

## Dọn dẹp

GitHub runner dọn service khi job kết thúc. Local thì dùng `docker compose -f labs/url-shortener/compose.yaml down`; chỉ thêm `--volumes` khi chủ động xóa database local của lab và đã kiểm tra không có dữ liệu cần giữ. Không chạy lệnh xóa RDS trong CI. Giữ YAML để bổ sung test và artifact; chi phí Actions phụ thuộc plan và thời gian runner, không dựa vào AWS Budget.
